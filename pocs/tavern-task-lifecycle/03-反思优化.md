## 方案回顾

**选定方案**：中策（Agent 指令引导 + 轻量级监控）

**核心思路**：

- 通过精心设计的 Agent 指令引导 Agent 自主完成五阶段流程
- 不引入复杂的状态机，依赖 Agent 的自主性
- 增加轻量级监控（文件监听 + 事件监听）
- 通过配置开关渐进式启用，向后兼容

## 边界情况检查

### 边界 1：任务执行中 Agent 崩溃/重启 🔴

**场景**：Agent 执行到阶段三时，应用崩溃或用户强制重启

**当前方案是否考虑？** ❌ 未考虑

**问题分析**：

- Agent 会话丢失，任务无法继续
- 已生成的文档（01~03）仍然保存在 `lifecycle/` 目录
- 但任务状态可能仍为 `in-progress`，TaskScheduler 会跳过（认为正在执行）

**优化方案**：

1. **恢复检测**（TaskScheduler 启动时）

   ```typescript
   // TaskScheduler.start() 中新增
   async checkAndRecoverTasks(): Promise<void> {
     const store = await TavernStore.getInstance();
     const tasks = await store.readIndex();

     const stuckTasks = tasks.filter(t =>
       t.status === 'in-progress' &&
       t.config?.useLifecycle &&
       Date.now() - new Date(t.updatedAt).getTime() > 30 * 60 * 1000 // 30 分钟无更新
     );

     for (const task of stuckTasks) {
       log.warn(`[TaskScheduler] Detected stuck task: ${task.id}, attempting recovery`);
       await this.recoverTask(task);
     }
   }
   ```

2. **恢复逻辑**

   ```typescript
   private async recoverTask(task: Task): Promise<void> {
     const workspace = await Env.getAgentWorkspaceDir(task.threadId!);
     const lifecycleDir = path.join(workspace, 'lifecycle');

     // 检测已完成的阶段
     const completedStages = await this.detectCompletedStages(lifecycleDir);
     const lastStage = completedStages[completedStages.length - 1];

     // 构造"恢复执行"的消息
     const message = `
     任务「${task.title}」需要恢复执行。

     已完成阶段：${completedStages.join(', ')}
     当前应继续：${this.getNextStage(lastStage)}

     请从 lifecycle/ 目录读取已有文档，继续执行未完成的阶段。
     `;

     // 重新提交
     const { agentExecutor } = await import('@main/ai/AgentExecutor');
     await agentExecutor.submit({
       sessionId: task.threadId!,
       message,
       builder: agentExecutor.createBuilderFromFactory('agent')!
     });
   }
   ```

**优化结果**：✅ 任务可恢复，不会丢失进度

### 边界 2：Agent 生成的文档格式错误 🟡

**场景**：Agent 生成的 `01-需求分析.md` 缺少必需章节

**当前方案是否考虑？** 🟡 部分考虑（有 DocumentValidator）

**问题分析**：

- DocumentValidator 只是告警，不阻塞执行
- 如果文档质量太差，后续阶段可能基于错误信息继续

**优化方案**：

1. **阈值控制**

   ```typescript
   // DocumentValidator 增加评分机制
   interface ValidationResult {
     valid: boolean;
     score: number; // 0-100 分
     errors: string[];
     warnings: string[];
   }

   // 在 LifecycleMonitor 中检查
   const result = validator.validate(filename, content);
   if (result.score < 60) {
     log.error(`[LifecycleMonitor] Document quality too low: ${result.score}/100`);

     // 发送修正指令
     await this.requestRevision(task, filename, result.errors);
   }
   ```

2. **自动修正**

   ```typescript
   private async requestRevision(task: Task, filename: string, errors: string[]): Promise<void> {
     const message = `
     文档「${filename}」格式不完整，请修正以下问题：
     ${errors.map((e, i) => `${i+1}. ${e}`).join('\n')}

     请重新编写该文档，确保包含所有必需章节。
     `;

     const { agentExecutor } = await import('@main/ai/AgentExecutor');
     await agentExecutor.submit({
       sessionId: task.threadId!,
       message,
       builder: agentExecutor.createBuilderFromFactory('agent')!
     });
   }
   ```

**优化结果**：✅ 低质量文档可被自动修正

### 边界 3：用户长时间不补充资料 🟡

**场景**：任务进入 `awaiting-input` 状态，用户忘记补充或不想补充

**当前方案是否考虑？** ❌ 未考虑

**问题分析**：

- 任务永久卡在 `awaiting-input` 状态
- 占用 ThreadStore 的会话资源

**优化方案**：

1. **超时自动取消**

   ```typescript
   // TavernStore 新增字段
   interface Task {
     awaitingInputSince?: number; // 进入 awaiting-input 的时间戳
   }

   // TaskScheduler 定期检查
   async checkStaleAwaitingTasks(): Promise<void> {
     const tasks = await store.readIndex();
     const staleTasks = tasks.filter(t =>
       t.status === 'awaiting-input' &&
       t.awaitingInputSince &&
       Date.now() - t.awaitingInputSince > 24 * 60 * 60 * 1000 // 24 小时
     );

     for (const task of staleTasks) {
       log.warn(`[TaskScheduler] Task ${task.id} awaiting input for too long, cancelling`);
       await store.updateTask(task.id, {
         status: 'cancelled',
         lastError: '用户 24 小时内未补充资料，任务已自动取消'
       });

       // 通知用户
       eventBus.emit('agent:event', {
         _event: 'notify',
         message: `任务「${task.title}」因长时间未补充资料已取消`,
         level: 'warning'
       });
     }
   }
   ```

2. **用户提醒**
   ```typescript
   // 进入 awaiting-input 状态 12 小时后发送提醒
   setTimeout(
     () => {
       eventBus.emit('agent:event', {
         _event: 'notify',
         message: `任务「${task.title}」等待补充资料已 12 小时，请及时处理`,
         level: 'info'
       });
     },
     12 * 60 * 60 * 1000
   );
   ```

**优化结果**：✅ 避免任务永久挂起

### 边界 5：文件操作权限问题 🟢

**场景**：`lifecycle/` 目录创建失败或文件写入失败

**当前方案是否考虑？** 🟡 部分考虑（有 try-catch）

**优化方案**：

```typescript
// LifecycleOrchestrator.createLifecycleDir()
private async createLifecycleDir(sessionId: string): Promise<string> {
  try {
    const workspace = await Env.getAgentWorkspaceDir(sessionId);
    const lifecycleDir = path.join(workspace, 'lifecycle');
    await fs.promises.mkdir(lifecycleDir, { recursive: true });

    // 验证可写性
    const testFile = path.join(lifecycleDir, '.test');
    await fs.promises.writeFile(testFile, 'test', 'utf-8');
    await fs.promises.unlink(testFile);

    return lifecycleDir;
  } catch (err) {
    log.error(`[LifecycleOrchestrator] Failed to create lifecycle dir:`, err);
    throw new Error(`无法创建 lifecycle 目录：${err.message}`);
  }
}
```

**优化结果**：✅ 文件操作失败会提前抛出异常，避免静默失败

## 安全评估

### 安全风险 1：Agent 写入敏感信息到文档 🟡

**场景**：任务涉及 API Key，Agent 将其写入 `01-需求分析.md`

**风险**：

- 文档文件存储在磁盘（明文）
- 可能泄露敏感信息

**缓解措施**：

1. **Prompt 中明确告知**

   ```
   ⚠️ 安全提示：
   - 不要将 API Key、密码等敏感信息写入文档
   - 如需记录，使用占位符（如 [用户已提供 API Key]）
   - 敏感信息应存储在任务的 userInputs 字段（加密存储）
   ```

2. **敏感信息检测**（可选，后续优化）

   ```typescript
   // DocumentValidator 中新增
   private detectSensitiveInfo(content: string): string[] {
     const patterns = [
       /api[_-]?key\s*[:=]\s*[\w-]+/i,
       /password\s*[:=]\s*\w+/i,
       /token\s*[:=]\s*[\w.-]+/i
     ];

     const found: string[] = [];
     for (const pattern of patterns) {
       const match = content.match(pattern);
       if (match) found.push(match[0]);
     }

     return found;
   }
   ```

**优化结果**：✅ 降低敏感信息泄露风险

---

### 安全风险 2：Agent 执行恶意代码 🔴

**场景**：任务描述包含恶意指令（如"删除所有文件"）

**风险**：

- Agent 有文件操作工具，可能执行破坏性操作
- 五阶段流程不能防御此类攻击

**缓解措施**：

1. **任务创建时的审查**（应用配置层面）

   ```typescript
   // 在 Gateway 的 tavern.createTask 中增加审查
   const dangerousKeywords = ['删除', 'rm -rf', '格式化', 'DROP TABLE'];
   const hasDanger = dangerousKeywords.some((k) => task.description.includes(k));

   if (hasDanger) {
     log.warn(`[Tavern] Task contains dangerous keywords: ${task.title}`);
     // 要求用户二次确认
   }
   ```

2. **Agent 工具权限控制**（已有机制）
   - 依赖 `coobee.json5` 中的 `security.sandbox` 配置
   - 敏感操作需要用户审批（HITL）

**优化结果**：✅ 依赖现有安全机制，无需额外改动

## 影响分析

### 对现有功能的影响

**改动**：`dispatchTask()` 方法新增分支逻辑

**影响范围**：

- 旧任务（`useLifecycle: false`）→ ✅ 无影响（走旧逻辑）
- 新任务（`useLifecycle: true`）→ 🔵 走新流程

**风险**：

- 🟢 低：分支清晰，互不干扰
- ✅ 可通过配置随时切换

**改动**：Task 类型新增 `config` 和 `lifecycleStage` 字段

**向后兼容性**：

- ✅ 字段都是可选（`?`）
- ✅ 旧任务没有这些字段，不影响读取
- ✅ 新字段不影响旧代码逻辑

**迁移成本**：

- ✅ 零成本：无需数据迁移

**影响**：

## 优化调整

基于以上反思，对中策方案进行以下调整：

### 调整 1：新增任务恢复机制 ✅

**原方案**：无恢复机制

**调整后**：

- 启动时检测 `in-progress` 的任务（30 分钟无更新）
- 自动检测已完成的阶段
- 构造"恢复执行"消息，重新提交

**实施优先级**：P0（核心功能）

---

### 调整 2：文档质量阈值控制 ✅

**原方案**：DocumentValidator 仅告警

**调整后**：

- 文档质量评分（0-100）
- 低于 60 分 → 自动发送修正指令
- Agent 重新编写文档

**实施优先级**：P1（质量保障）

---

### 调整 3：awaiting-input 超时机制 ✅

**原方案**：任务可能永久挂起

**调整后**：

- 24 小时未补充资料 → 自动取消
- 12 小时发送提醒通知

**实施优先级**：P1（避免资源浪费）

---

### 调整 4：简化前端界面（MVP） ✅

**原方案**：完整的进度展示 UI（~200 行）

**调整后**（MVP）：

- 仅显示"当前阶段"文字（~50 行）
- 阶段进度条（5 个圆点，~50 行）
- 详细文档预览作为后续优化

**实施优先级**：P0（MVP 核心功能）

**理由**：

- ✅ 降低前端开发成本（减少 100 行）
- ✅ 快速验证后端逻辑
- ✅ 前端 UI 可迭代优化

---

### 调整 5：默认配置调整 ✅

**原方案**：`task.config.useLifecycle` 默认 `false`

**调整后**（分阶段）：

- **MVP 阶段**：默认 `false`（向后兼容，低风险）
- **验证后**（2 周内）：默认改为 `true`（全面推广）
- **配置项**：用户可在应用配置中设置全局默认值

**实施优先级**：P0（风险控制）

## 性能优化建议

### 优化 1：智能识别任务复杂度 ✅

**问题**：所有启用 `useLifecycle` 的任务都走五阶段，即使是简单任务

**优化方案**：

```typescript
// 在 LifecycleOrchestrator.execute() 中增加复杂度判断
private isComplexTask(task: Task): boolean {
  const indicators = [
    task.description.length > 200, // 描述较长
    task.files.length > 3, // 涉及多个文件
    /重构|迁移|架构|设计/.test(task.description), // 包含复杂关键词
    task.amount > 100 // 金额较高（用户期望质量高）
  ];

  return indicators.filter(Boolean).length >= 2; // 满足 2 个条件即为复杂任务
}

async execute(task: Task, sessionId: string): Promise<void> {
  if (!this.isComplexTask(task)) {
    log.info(`[LifecycleOrchestrator] Task ${task.id} is simple, using fast mode`);
    // 简化流程：只要求需求分析 + TODO + 验收
    await this.executeFastMode(task, sessionId);
  } else {
    // 完整五阶段流程
    await this.executeFullMode(task, sessionId);
  }
}
```

**效果**：

- ✅ 简单任务执行时间降低 50%
- ✅ Token 成本降低 60%

**实施优先级**：P1（性能优化）
