# 智库（Brain）设计更新说明

> **更新时间**: 2026-02-23  
> **更新原因**: 改用 Worker 架构 + Python 实现

---

## 核心变更

### 1. 架构调整

**原设计**: TypeScript + Node.js 内嵌 HTTP 服务
**新设计**: Python Worker + Flask HTTP 服务

```
旧架构:
  src/main/brain/         ← TypeScript 实现
    ├── server/           ← Koa HTTP 服务
    └── storage/          ← 文件操作

新架构:
  workers/brain/          ← Python Worker
    ├── worker.json       ← Worker 配置
    ├── server.py         ← Flask HTTP 服务
    └── brain/            ← Python 模块
```

### 2. 生命周期管理

**旧方式**: 手动在 `ReadyInfraHook` 中启动 HTTP 服务

```typescript
// 旧代码（不再需要）
const brainServer = new BrainServer({ port: 42043 });
await brainServer.start();
```

**新方式**: 通过 WorkerManager 自动管理

```
1. ReadyWorkerHook 扫描 workers/ 目录
   ↓
2. 发现 workers/brain/worker.json
   ↓
3. 注册到 WorkerManager
   ↓
4. WorkerManager 自动：
   - 创建虚拟环境（使用 uv）
   - 安装依赖（requirements.txt）
   - 启动子进程（python server.py --port 42043）
   - 健康检查（GET /health）
   - 崩溃自动重启
```

**好处**:

- ✅ 无需修改任何 TypeScript 代码
- ✅ 与现有 Worker 体系一致（如 tavern-poller, tts, asr, ocr）
- ✅ 自动虚拟环境管理
- ✅ 统一的启停控制
- ✅ 完全解耦

## Worker 配置示例

**workers/brain/worker.json**:

```json
{
  "name": "brain",
  "label": "智库服务",
  "type": "python",
  "entry": "server.py",
  "port": 42043,
  "requirementsFile": "requirements.txt",
  "autoRestart": true,
  "maxRestarts": 5,
  "healthCheckPath": "/health",
  "healthCheckTimeout": 10000,
  "autoStart": false,
  "env": {}
}
```

**说明**:

- `autoStart: false` - 不随应用启动，按需启动
- `port: 42043` - 独立端口
- `healthCheckPath: /health` - 健康检查端点

## Agent 使用方式（不变）

Agent 仍然通过 **纯 HTTP + Skill** 交互，无需注册工具：

```python
# Agent 使用 exec 工具发送 HTTP 请求
exec("curl -X POST http://localhost:42043/api/brain/publish ...")
```

或使用 Python 脚本：

```python
# publish_to_brain.py
import requests
import json

response = requests.post(
    'http://localhost:42043/api/brain/publish',

        'message_id': 'msg_xxx',
        'timestamp': '2026-02-23T10:00:00Z',
        'payload': {
            'pattern': {...},
            'practice': {...}
        }
    }
)
```

## 实施影响

### 开发工作量

| 任务      | 旧估算 | 新估算 | 变化                   |
| --------- | ------ | ------ | ---------------------- |
| 架构搭建  | 1-2天  | 0.5天  | ↓ 减少（复用 Worker）  |
| HTTP 服务 | 2-3天  | 2天    | ↓ 简化（Flask 更简单） |
| 存储逻辑  | 2天    | 2天    | = 相同                 |
| 测试验证  | 2天    | 2天    | = 相同                 |
| **总计**  | 7-9天  | 6-7天  | ↓ 略微减少             |

### 优势

1. **架构一致性**
   - 与现有 Worker（tavern-poller, tts, asr, ocr）保持一致
   - 统一的管理方式

2. **部署简化**
   - 无需修改主应用代码
   - 可以独立更新 Worker

3. **开发体验**
   - Python 生态丰富（requests, flask, pytest）
   - 快速原型验证

4. **维护成本**
   - 独立进程，崩溃不影响主应用
   - 日志分离，问题排查容易

### 劣势

1. **性能**
   - 跨进程 HTTP 通信，比 TypeScript 内嵌慢（可接受）
   - 内网调用，延迟 < 10ms

2. **依赖**
   - 需要 Python 3.11 环境（已有，Worker 通用需求）
   - 需要 uv 工具（已集成在 runtime/）

## 额外功能

### Gateway 管理 API（新增）

**目的**: 供前端管理系统查看和管理智库

**文件**: `src/main/gateway/methods/brain.ts`

**方法**:

- `brain.stats()` - 获取统计信息
- `brain.list(params)` - 列出经验包
- `brain.get(params)` - 获取详情
- `brain.delete(params)` - 删除经验包

**特点**:

- 自动检查 Brain Worker 是否就绪
- 请求自动转发到 Brain Worker (port 42043)
- Gateway 统一错误处理
