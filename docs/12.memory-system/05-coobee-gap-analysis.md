# coobee-ai 记忆系统现状与 memU 对比分析

> 本文档从 8 个维度对比 coobee-ai 当前记忆系统与 memU 方案的差距，并给出优先级排序和改进建议。

---

## 1. coobee-ai 当前记忆系统架构

```
┌─────────────────────────────────────────────────────────┐
│                  当前记忆系统                             │
│                                                         │
│  ┌──────────────────┐      ┌────────────────────────┐  │
│  │ memory-thread ext   │      │    memory tool         │  │
│  │ (自动捕获/注入)   │      │ (LLM 主动调用)         │  │
│  └────────┬─────────┘      └───────────┬────────────┘  │
│           │                            │               │
│  ┌────────▼────────────────────────────▼────────────┐  │
│  │              Markdown 文件存储                     │  │
│  │  MEMORY.md (核心记忆)                             │  │
│  │  memory/*.md (分类记忆)                           │  │
│  └───────────────────────────────────────────────────┘  │
│                                                         │
│  ┌───────────────────────────────────────────────────┐  │
│  │          AgentEnvInjector                          │  │
│  │  execution_protocol 中嵌入记忆使用指导             │  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 1.1 memory-thread extension

**写入（agent_end hook）**：

- 使用 regex 信号词检测（`记住`、`总是`、`经验`、`教训` 等）
- 匹配到信号词 → 按分类写入 `memory/{date}.md`
- 无信号词但输出较长 → 提取摘要写入

**读取（before_agent_start hook）**：

- 读取 `MEMORY.md` 作为 `core_memory`
- 读取 `memory/*.md`，按关键词子串匹配筛选 `recalled_memories`
- 注入到 Agent 的 instructions 中

### 1.2 memory tool

LLM 通过 `memory` tool 主动操作记忆文件：

- `memory(action='list')` — 列出记忆文件
- `memory(action='read', file='...')` — 读取文件内容
- `memory(action='write', file='...', content='...', append=true)` — 写入/追加
- `memory(action='search', query='...')` — 搜索记忆

### 1.3 AgentEnvInjector

在 execution_protocol 中嵌入记忆使用指导：

- 指导 LLM 在任务开始时检查已有记忆
- 指导 LLM 在任务结束时保存有价值的知识
- 提供具体的 `memory` tool 调用示例

## 2. 八维度差距分析

### 2.1 存储层

| 维度     | coobee-ai            | memU                                       | 差距等级 |
| -------- | -------------------- | ------------------------------------------ | -------- |
| 存储格式 | Markdown 纯文本文件  | 三层关系模型（Resource → Item → Category） | **严重** |
| 数据结构 | 无结构（自由文本）   | 强类型（Pydantic Model + 固定字段）        | **严重** |
| 向量索引 | 无                   | embedding 向量 + 余弦搜索                  | **严重** |
| 持久化   | 文件系统（原子写入） | SQLite / Postgres（ACID 事务）             | 中等     |

**影响**：无法进行语义检索，只能依赖简单的关键词子串匹配，导致检索召回率极低。

### 2.2 检索层

| 维度     | coobee-ai                                     | memU                                                  | 差距等级 |
| -------- | --------------------------------------------- | ----------------------------------------------------- | -------- |
| 检索方式 | 关键词子串匹配（`content.includes(keyword)`） | embedding 语义搜索 + LLM 排名                         | **严重** |
| 排名策略 | 无排名（命中即返回）                          | Salience 评分（similarity × reinforcement × recency） | **严重** |
| 分层检索 | 无（全量扫描）                                | Category → Item → Resource 三层渐进                   | 中等     |
| 查询理解 | 无（直接匹配原文）                            | LLM query rewrite（代词解析、上下文补充）             | 中等     |

**影响**：用户问 "我之前提到的那个项目" 时，当前系统完全无法理解和检索。

### 2.3 写入层

| 维度     | coobee-ai                            | memU                                                    | 差距等级 |
| -------- | ------------------------------------ | ------------------------------------------------------- | -------- |
| 捕获机制 | regex 信号词检测 + LLM 被动调用      | LLM 主动提取（每种类型独立 prompt）                     | **严重** |
| 提取精度 | 极低（仅匹配 "记住"、"总是" 等词汇） | 高（精心设计的 prompt + XML 输出）                      | **严重** |
| 类型化   | 无类型区分                           | 6 种类型（profile/event/knowledge/behavior/skill/tool） | **严重** |
| 去重     | 无                                   | content_hash + reinforcement_count                      | 中等     |

**影响**：大量有价值的信息（偏好、知识、经验）在对话中流失，未被捕获。实测使用多次后几乎无记忆产生。

### 2.4 类型系统

| 维度       | coobee-ai    | memU                                                | 差距等级 |
| ---------- | ------------ | --------------------------------------------------- | -------- |
| 记忆类型   | 无           | 6 种（profile/event/knowledge/behavior/skill/tool） | **严重** |
| 分类管理   | 按日期文件名 | 10 个默认分类 + 自定义分类 + 分类摘要               | 中等     |
| 按类型过滤 | 不可能       | 可按 memory_type 精确过滤                           | 中等     |

**影响**：无法区分 "用户偏好" 和 "项目知识"，检索时无法按类型精准定位。

### 2.5 时效性

| 维度     | coobee-ai        | memU                                       | 差距等级 |
| -------- | ---------------- | ------------------------------------------ | -------- |
| 强化机制 | 无               | reinforcement_count（重复提及 → 权重增加） | 中等     |
| 时间衰减 | 无               | 指数半衰期衰减（默认 30 天半衰期）         | 中等     |
| 新鲜度   | 所有记忆权重相同 | 新记忆权重高，旧记忆渐衰                   | 中等     |

**影响**：三年前的临时信息和昨天的重要偏好在检索时具有相同权重。

### 2.6 多用户/多 Agent

| 维度     | coobee-ai                 | memU                                | 差距等级 |
| -------- | ------------------------- | ----------------------------------- | -------- |
| 隔离方式 | 按 workspace 文件目录隔离 | user_id/agent_id 作用域（数据库级） | 轻微     |
| 细粒度   | workspace 级              | user_id + agent_id + session_id     | 轻微     |

**影响**：当前方案在单用户桌面应用场景下基本够用，但无法支持多 Agent 间记忆隔离。

### 2.7 多模态

| 维度     | coobee-ai | memU                                   | 差距等级 |
| -------- | --------- | -------------------------------------- | -------- |
| 支持模态 | 仅文本    | text/image/audio/video                 | 轻微     |
| 预处理   | 无        | 按模态分发（vision LLM、视频帧提取等） | 轻微     |

**影响**：当前场景（语音对话 → 文本转写）仅涉及文本，多模态为未来扩展需求。

### 2.8 可扩展性

| 维度          | coobee-ai    | memU                                      | 差距等级 |
| ------------- | ------------ | ----------------------------------------- | -------- |
| Pipeline 编排 | 硬编码逻辑   | WorkflowStep + PipelineManager（可插拔）  | 中等     |
| 存储切换      | 绑定文件系统 | Repository Protocol + Factory（一键切换） | 中等     |
| Prompt 定制   | 无           | 模块化 prompt block（可单独替换）         | 轻微     |

## 3. 差距优先级矩阵

```
          严重                    中等                   轻微
  ┌─────────────────┐   ┌─────────────────┐   ┌─────────────────┐
  │ 存储无结构化     │   │ 去重机制缺失    │   │ 多用户隔离      │
  │ 无向量搜索       │   │ 分层检索缺失    │   │ 多模态支持      │
  │ 检索纯关键词     │   │ 查询理解缺失    │   │ Prompt 定制     │
  │ 无 Salience 排名 │   │ 强化/衰减缺失   │   │                 │
  │ 写入靠 regex     │   │ Pipeline 编排   │   │                 │
  │ 无类型区分       │   │ 存储可切换      │   │                 │
  └─────────────────┘   └─────────────────┘   └─────────────────┘
         P0 必须修复          P1 重要改进           P2 未来扩展
```

## 4. 根本问题诊断

### 4.1 核心病因

**coobee-ai 记忆系统"不产生记忆"的根本原因**：

1. **Regex 信号词检测失效**
   - `\b` 在 CJK 字符上不生效（已修复，但说明设计思路有问题）
   - 信号词覆盖面太窄，绝大多数有价值的对话不包含 "记住"、"总是" 等关键词
   - 本质上是**规则匹配**，而非**语义理解**

2. **LLM 未被充分引导使用 memory tool**
   - AgentEnvInjector 中的指导仍然偏被动（"save valuable knowledge"）
   - LLM 在大多数对话中不会主动调用 memory tool
   - 缺乏对 "什么值得记忆" 的明确指标

3. **检索质量太差导致负反馈**
   - 关键词匹配召回率极低
   - 注入的记忆经常不相关（因为没有语义匹配）
   - LLM 学会忽略 recalled_memories → 进一步降低记忆使用频率

### 4.2 解决方向

```
规则匹配 → LLM 主动提取（解决写入问题）
关键词搜索 → 语义向量搜索（解决检索问题）
无结构文本 → 结构化数据模型（解决存储问题）
无时效性 → Salience 评分（解决排名问题）
```

---

## 5. 改进建议（按优先级）

### P0: 必须修复（Phase 1-2）

1. **结构化存储**：从 Markdown 迁移到 SQLite + 三层数据模型
2. **LLM 主动提取**：agent_end 时用 LLM 提取记忆（替换 regex）
3. **语义检索**：embedding 向量搜索替换关键词匹配
4. **类型化**：至少支持 profile/event/knowledge 三种核心类型

### P1: 重要改进（Phase 3）

5. **Salience 排名**：similarity × reinforcement × recency
6. **去重 + 强化**：content_hash 检测重复，重复时累加计数
7. **查询重写**：LLM 解析代词和隐式引用

### P2: 未来扩展（Phase 4-5）

8. **分层检索**：Category → Item 渐进检索
9. **Pipeline 编排**：可插拔的 WorkflowStep
10. **多 Agent 记忆隔离**：per-agent 作用域
