# 智能体学习系统 (Agent Learning System)

> **专项目标**：设计并实现智能体的自主学习和知识积累机制，让智能体在使用过程中不断进化、变得越来越智能。

---

## 核心问题

### 问题根源

- **应用层和训练层混淆**：智能体在处理日常任务的同时想要进行训练和进化，导致目录不知道怎么放、数据不知道存在哪
- **被动式学习**：完全依赖 LLM 自己决定是否积累经验，太被动，很可能不做
- **缺乏量化评估**：无法衡量智能体是否真的变强了

### 核心理念（分层解耦）

```
第一层（底层）：智能体训练与进化
  ↓ 知识积累、能力提升、长期记忆

第二层（中间层）：用户工程目录
  ↓ 用户的代码、文档、资产（持久化，但不属于智能体）

第三层（应用层）：任务执行的临时工作区
  ↓ 当前会话的临时文件、中间结果（可抛弃）
```

**关键原则**：

- ✅ 训练归训练，负责长期积累（Agent Home）
- ✅ 运行归运行，负责项目目录+临时任务（Workspace）
- ✅ 两层互不干扰，但又能共用知识库和记忆

---

## 实施方案

### 方案一：任务完成后的自动知识提取（应用层）

**定位**：程序化保证每个任务完成后都会提取经验

**核心机制**：

1. 监听 `thread:status` 事件（任务完成时触发）
2. 自动调用专门的"知识提取 Agent"
3. 提取：问题、解决方案、用户反馈、可复用知识
4. 存储到 Agent Home（跨会话持久化）
5. 异步同步到 brain/shared-drive（跨智能体共享）

**关键挑战**：

- 避免死循环（知识提取任务本身不能再触发提取）
- 并发控制（多个任务同时完成时的处理）
- 幂等性（同一个任务不重复提取）

**文档**：[01-task-knowledge-extraction-design.md](./01-task-knowledge-extraction-design.md)

---

### 方案二：独立的训练模式（训练层）

**定位**：集中式、迭代式的智能体强化训练

**核心机制**：

1. 独立的"训练视图"（UI）
2. 定义训练目标（基于 dimension-architect 技能）
3. 设置训练次数（1000 次、10000 次）
4. 程序驱动循环训练
5. 基于 eval-refine-loop 持续优化
6. 训练结果固化到 Agent Home

**关键特点**：

- 不是日常使用中的顺便训练
- 完全独立的功能模块
- 程序驱动，不依赖 LLM 主动性
- 可量化、可追溯的训练过程

## 参考资料

### 已有机制

- `KnowledgeArchiveJob`：定时扫描历史任务并归档（每日凌晨 2 点）
- `dimension-architect` Skill：需求维度量化
- `eval-refine-loop` Skill：评估-改良闭环
- `self-reflection` Skill：自我评估与修复

### 相关技术

- Extension 系统：生命周期钩子、事件监听
- EventBus：`thread:status`、`thread:created` 等事件
- Agent Home：智能体的持久化空间（`homes/{agentId}/`）
- Brain/Tavern：结构化的经验库和智库

## 关键决策点（待讨论）

### 方案一：任务知识提取

1. ❓ 失败的任务是否提取知识？
2. ❓ 并发控制：N=1（串行）还是 N=2（可并发 2 个）？
3. ❓ 何时同步到 brain/shared-drive？（立即 vs 延迟）
4. ❓ 提取粒度：整个任务 vs 每个工具调用？
5. ❓ 历史任务是否补录？（批量补录 vs 只处理新任务）

### 方案二：训练模式

1. ❓ 训练目标如何定义？（基于哪些维度）
2. ❓ 训练数据集从何而来？（合成 vs 真实任务）
3. ❓ 训练循环的终止条件？（达标 vs 次数上限）
4. ❓ 训练结果如何固化到 Agent 定义？
5. ❓ 如何防止过拟合？（泛化能力）
