---

## 🎯 核心理念

**训练的目的**：让 Agent 真正变强，而不只是评估表现

**关键原则**：

1. 训练必须有明确的目标（自动生成，科学量化）
2. 训练必须基于真实知识（知识库，而非随意数据）
3. 训练必须有质检保障（最多重试 3 次）
4. 训练必须有成果积累（Agent 能力真正提升）

## 📋 完整训练流程

### 阶段 0：准备训练目标（动态生成）

#### 用户操作

```
用户输入（口述或文本）：
  "我要提升 app-copilot 的代码生成能力"
```

#### 系统处理

```
1. 解析用户意图
   → 提取关键信息：
      - 被训练 Agent: app-copilot
      - 训练目标: 代码生成能力

2. 调用 dimension-architect 技能
   → 输入：训练目标描述 "代码生成能力"
   → 处理：
      - 分析这个能力包含哪些维度
      - 为每个维度设计量化标准
      - 分配权重
      - 设定达标阈值
   → 输出：
      {
        "name": "代码生成能力",
        "description": "评估智能体生成高质量代码的能力",
        "dimensions": [
          {
            "name": "correctness",
            "label": "正确性",
            "description": "代码功能是否正确实现",
            "weight": 35,
            "criteria": "基于测试用例验证功能完整性和逻辑正确性"
          },
          {
            "name": "quality",
            "label": "代码质量",
            "description": "代码可读性和可维护性",
            "weight": 25,
            "criteria": "命名规范、结构清晰、注释适当"
          },
          {
            "name": "performance",
            "label": "性能",
            "description": "算法效率和资源使用",
            "weight": 20,
            "criteria": "时间和空间复杂度合理"
          },
          {
            "name": "best-practices",
            "label": "最佳实践",
            "description": "是否遵循语言和领域最佳实践",
            "weight": 20,
            "criteria": "现代语言特性、设计模式、安全性"
          }
        ],
        "threshold": 75
      }

3. 保存训练目标（可选）
   → 保存到：~/coobee-data/training/goals/code-generation.json
   → 供未来复用
```

#### 关键智能体

- **dimension-architect 技能**（不是 Agent，是 LLM 技能）
  - 已存在，无需开发
  - 专门用于生成量化评估体系

### 阶段 1：生成训练数据（基于知识库）

#### 用户操作

```
前端界面：
  1. 选择被训练智能体：app-copilot
  2. 训练目标：已生成（上一步的输出）
  3. 数据源类型：知识库 ← 新增
  4. 知识库路径：brain/coding-standards ← 新增
  5. 训练轮次：100
  6. 训练策略：sequential
```

#### 系统处理

```
1. 调用 training-data-generator Agent（批量生成）

   输入参数：
     - knowledgeBasePath: "brain/coding-standards"
     - trainingGoal: { ...训练目标定义 }
     - targetCount: 100 （训练轮次）
     - trainTestRatio: 0.8 （训练集:测试集 = 80:20）

   Prompt 示例：
     "请从知识库 brain/coding-standards 读取所有内容，
      基于训练目标"代码生成能力"及其评估维度，
      生成 100 个训练任务（训练集 80 + 测试集 20）。

      要求：
      - 任务描述清晰、可执行
      - 覆盖所有评估维度
      - 难度分布：简单30% / 中等50% / 困难20%
      - 输出 JSON 格式

      如果内容过多无法一次生成，请先生成 30 个，
      后续会继续请你生成剩余部分。"

2. Agent 处理

   第 1 次调用（生成 30 个）：
     → 读取 brain/coding-standards（使用 read 工具）
     → 分析内容，提取知识点
     → 生成 30 个任务
     → 返回 JSON

   第 2 次调用（生成 30 个）：
     → 基于第 1 次的上下文
     → 继续生成，避免重复
     → 返回 JSON

   第 3-4 次...直到达到 100 个

3. 系统汇总

   合并所有生成结果：
     {
       "name": "代码生成训练集（从 brain/coding-standards）",
       "version": "1.0.0",
       "category": "code-generation",
       "sourceType": "knowledge-base",
       "sourcePath": "brain/coding-standards",
       "trainSet": [80个任务],
       "testSet": [20个任务]
     }

   保存到会话：
     session.dataset = {...上述数据}
```

#### 关键智能体

- **training-data-generator Agent**
  - 需要增强：支持读取知识库
  - 需要增强：支持批量生成（分批调用）
  - 工具：read（读取知识库）

### 阶段 3：成果积累（训练结束后）

#### 核心问题

**用户的疑问**：

> "被训练的智能体要有成果积累，不能白训练。  
> 但我不知道怎么做，你以前有没有考虑这块？"

#### 当前设计的局限

```
当前设计（TrainingVersionManager）：
  → 训练完成后创建 Agent 版本快照
  → 保存到：~/coobee-data/homes/app-copilot/versions/{id}.json
  → 可以切换版本使用

❌ 问题：
  - 只是"保存了一个时间点的 Agent 定义"
  - Agent 的 instructions 没有变化
  - 下次使用时，Agent 不知道自己训练过什么
  - "版本"只是备份，不是"能力提升"
```

#### 成果积累的本质

**训练成果 = 训练中学到的经验教训**

```
100 轮训练后，我们得到：
  ✅ 100 个任务的执行记录
  ✅ 每个任务的评估反馈
  ✅ 高频失败模式
  ✅ 有效的改进建议

这些数据可以提炼出：
  → 常见错误类型
  → 最佳实践总结
  → 维度提升要点
  → 注意事项清单
```


```
## 🤖 完整的 Agent 调用链

### 训练前（准备阶段）

```

1. dimension-architect 技能（1 次）

```
### 训练中（每条数据）

```

场景 A：首次达标（45%）
被训练 Agent (1次) + evaluator (1次) = 2 次

场景 B：二次达标（30%）
被训练 Agent (2次) + evaluator (2次) + coach (1次) = 5 次

场景 C：三次达标（7%）
被训练 Agent (3次) + evaluator (3次) + coach (2次) = 8 次

场景 D：最终失败（18%）
被训练 Agent (3次) + evaluator (3次) + coach (2次) = 8 次

100 条数据：约 400 次调用

```

### 训练后（成果积累）

```

   → 分析训练记录，提取核心经验
2. 系统自动操作
   → 更新 Agent instructions
   → 保存详细经验到 knowledge/
   → 生成训练报告

```

## 🤔 开放式问题

### 关于"训练让 Agent 变强"的本质

**现实**：
- LLM 本身无法"学习"（每次调用都是无状态的）
- 所谓"变强"只能通过：
  1. 更好的 instructions（告诉它注意什么）
  2. 更丰富的 knowledge（给它查询的资料）
  3. 更好的 tools/skills（扩展能力）

**训练的价值**：
- 不是让 LLM 参数变化（那是 fine-tuning）
- 而是通过大量实践，找出 Agent 的弱点和改进点
- 把这些改进点"写入"Agent 定义
- 下次使用时，Agent 会按照这些经验行事

**类比**：
- 就像给员工写"工作手册"
- 训练 = 发现问题 → 编写解决方案 → 更新手册
- 下次遇到类似问题，员工查手册就知道怎么做
```
