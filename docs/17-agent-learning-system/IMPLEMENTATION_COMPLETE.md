## 🏗️ 架构特性

### Agent-first 架构

所有 LLM 交互都通过专用 Agent：

```
TrainingExecutor
    ↓
AgentDelegator (重试/超时/错误处理)
    ↓
ChannelRuntime.executeAgent()
    ↓
├─ training-evaluator    (评估输出)
├─ training-coach        (生成建议)
└─ training-data-generator (生成任务)
```

### 多策略支持

1. **Sequential**: 串行训练（稳定）
2. **Parallel**: 并行训练（快速，3-5倍提速）
3. **Adaptive**: 自适应训练（智能调整难度）
4. **Weakness-Targeted**: 弱点强化（针对性训练）

### 防过拟合机制

- ✅ 训练集/测试集分离
- ✅ TestSetValidator 定期验证
- ✅ 过拟合检测与告警

### 智能化特性

- ✅ 弱点维度自动识别（WeaknessAnalyzer）
- ✅ 难度自适应调整（AdaptiveDifficultyManager）
- ✅ 针对性数据生成（TargetedDataGenerator）
- ✅ 教练建议系统

### 版本管理

- ✅ 自动创建训练后版本
- ✅ 版本对比与回滚
- ✅ 版本标签与描述

## 🎓 使用流程

### 基础训练流程

1. **创建训练会话**
   - 选择要训练的 Agent
   - 选择训练目标（维度体系）
   - 配置训练轮次和策略

2. **执行训练**
   - 系统自动执行训练循环
   - 实时显示进度和得分
   - 支持暂停/恢复/停止

3. **分析结果**
   - 查看训练曲线和维度雷达图
   - 运行弱点分析识别薄弱环节
   - 查看教练建议

4. **固化成果**
   - 创建训练后的 Agent 版本
   - 对比训练前后差异
   - 切换到新版本使用

### 增量训练流程

1. 查看已完成训练的弱点分析
2. 点击"继续训练"
3. 系统自动针对弱点维度生成新任务
4. 继续训练 100-500 轮
5. 再次分析，验证提升效果

### 遇到的挑战

1. **类型定义复杂**：嵌套对象类型定义需要反复调整
2. **测试环境搭建**：文件系统依赖、临时目录管理
3. **并发测试问题**：`Date.now()` 生成重复 ID 的问题
4. **风格不一致**：初始实现使用 Tailwind utility classes，需要重构

### 解决方案

1. **渐进式类型完善**：先实现功能，再完善类型
2. **临时文件管理**：使用 `fs.mkdtempSync` 和 `afterEach` 清理
3. **时间戳唯一性**：添加小延迟确保 `Date.now()` 差异
4. **设计系统对齐**：统一使用 CSS 变量和语义化类名
