# 实时语音识别测试指南

## 快速测试流程

### 1. 启动应用

```bash
pnpm dev
```

### 2. 观察 ASR Worker 启动

打开应用后，在底部状态栏观察：

- **ASR 状态指示器**：
  - 🔴 初始化中（红色/琥珀色）
  - 🟢 就绪（绿色）

等待 ASR Worker 启动完成（通常 5-10 秒）。

### 3. 开始说话测试

ASR 就绪后，麦克风会自动启动，观察：

- **麦克风状态**：显示"正在聆听..."（红点闪烁）
- **实时文字**：说话时会实时显示识别文本（蓝底）

### 4. 测试 VAD 功能

VAD（语音活动检测）会在你**停顿 1.2 秒**后触发识别。

**测试步骤**：

1. **说一句完整的话**：例如"今天天气真不错"
2. **保持静音 1-2 秒**：不要说话
3. **观察结果**：识别结果会自动发送到聊天窗口

**预期效果**：

- 识别出完整的句子
- 没有断句或截断
- 延迟在 300-500ms（从停顿到文字显示）

### 5. 测试连续说话

**测试场景**：不间断说话超过 20 秒

**预期行为**：

- 系统会在 20 秒时自动触发识别（安全阀）
- 识别结果发送到聊天
- 继续监听后续语音

### 6. 测试静音切换

点击底部的"静音"按钮：

- ✅ 静音后：麦克风仍在运行，但不发送数据
- ✅ 取消静音：恢复正常识别

## 性能指标

### 预期延迟（从说话结束到文字显示）

| 阶段       | 旧实现 (WebM) | 新实现 (PCM)  |
| ---------- | ------------- | ------------- |
| 音频转码   | 100-300ms     | <1ms          |
| 网络传输   | ~50ms         | ~20ms         |
| ASR 推理   | 200-500ms     | 200-500ms     |
| **总延迟** | **500-800ms** | **300-500ms** |

### CPU 占用

- **旧实现**：30-50%（含 ffmpeg 子进程）
- **新实现**：20-30%（纯 Python + FunASR）

## 常见问题排查

### 1. 麦克风权限

**症状**：提示"麦克风权限被拒绝"

**解决**：

- macOS: 系统设置 → 隐私与安全性 → 麦克风 → 允许 Coobee AI
- 重启应用

### 2. ASR Worker 启动失败

**症状**：ASR 状态一直显示"初始化中"或"错误"

**排查步骤**：

```bash
# 检查 Worker 日志
cat ~/Library/Logs/coobee-ai/workers/asr.log

# 手动测试 ASR Worker
cd workers/asr
source venv/bin/activate
python server.py --port 18100
```

### 3. 识别延迟高

**症状**：说话后 2-3 秒才出现文字

**原因**：

- VAD 静音阈值过高（误判为一直在说话）
- 网络连接不稳定

**调整 VAD 参数**（workers/asr/server.py）：

```python
SILENCE_THRESHOLD = 300       # 降低此值（如 200）
SILENCE_DURATION_SEC = 1.2    # 缩短此值（如 0.8）
```

### 4. 识别断句不准确

**症状**：长句子被拆成多个短句

**原因**：静音阈值太低，把正常停顿当成句子结束

**调整**：

```python
SILENCE_THRESHOLD = 300       # 提高此值（如 500）
SILENCE_DURATION_SEC = 1.2    # 延长此值（如 1.5）
```

### 5. 识别出幻觉文本

**症状**：识别结果重复或包含大量无关文字

**原因**：音频质量差或环境噪音过大

**当前防护**：

- `clean_asr_output()` 会检测输出字数 > 音频时长 × 15 字/秒
- 超过阈值会自动截断

**改进建议**：

- 使用外置麦克风
- 减少环境噪音
- 提高 `SILENCE_THRESHOLD`（过滤噪音）

## 高级测试

### 测试降采样质量

打开浏览器控制台（DevTools），查看日志：

```
[VoicePanel] AudioContext: 48000 Hz → 降采样到 16000 Hz (比率 3.0:1)
```

**验证点**：

- 比率应为整数（如 3:1、2:1），质量最佳
- 非整数比率（如 2.75:1）也能工作，但略有失真

### 测试 VAD 触发时机

观察后端日志：

```
[ASR] [VAD] 开始说话 pos=32000
[ASR] [VAD] 检测到停顿 (语音 2.1s, 静音 1.3s)
[ASR] 音频片段: 2.1s, 67200 bytes
[ASR] 识别: 2.1s 音频 | wav=0ms 推理=450ms | "今天天气真不错"
```

**验证点**：

- `wav=` 接近 0ms（证明无 ffmpeg 开销）
- `推理=` 在 200-800ms（正常范围）

### 压力测试

**测试场景**：连续说话 5 分钟

**预期结果**：

- CPU 稳定在 20-30%
- 内存占用稳定（PCM buffer 自动清空）
- 无延迟累积（每次识别独立）

## 配置优化建议

### 低延迟场景（实时对话）

```python
# workers/asr/server.py
SILENCE_THRESHOLD = 400
SILENCE_DURATION_SEC = 0.8
MAX_UTTERANCE_SEC = 10.0
```

### 高准确率场景（口述记录）

```python
SILENCE_THRESHOLD = 200
SILENCE_DURATION_SEC = 1.5
MAX_UTTERANCE_SEC = 30.0
```

### 嘈杂环境

```python
SILENCE_THRESHOLD = 800       # 提高阈值
SILENCE_DURATION_SEC = 1.0
```

## 后续优化方向

1. **VAD 模型替代**：使用 Silero VAD 替代简单能量检测
2. **AudioWorklet 替代 ScriptProcessor**：更低延迟（ScriptProcessor 已废弃）
3. **流式识别**：FunASR 支持 chunk-based 推理（当前是 batch）
4. **热词注入**：用户自定义专业词汇提升准确率
