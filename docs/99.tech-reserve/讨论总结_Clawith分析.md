# Clawith 项目分析总结

> 讨论时间：2026-03-08
> 分析对象：Clawith —— OpenClaw for Teams

---

## 📌 一、项目概述

**Clawith** 是一个开源的**企业级多智能体协作平台**，定位为：

- ❌ 不是个人助理工具
- ✅ 是**组织的数字员工管理平台**

**核心特点**：

- 每个 AI Agent 拥有**持久身份**、**长期记忆**、**独立工作空间**
- 支持多 Agent 组成团队协作
- 面向企业多租户场景设计

## 🔧 二、多核部署与代码执行方案

### 2.1 代码执行的实现方式

Clawith 采用**双模式架构**：

#### ✅ 模式一：轻量级进程执行（实际使用）

**实现位置**：`backend/app/services/agent_tools.py` 中的 `_execute_code()` 函数

**核心机制**：

```python
# 使用 Python asyncio 创建子进程
proc = await asyncio.create_subprocess_exec(
    *cmd_prefix, str(script_path),
    cwd=str(work_dir),
    stdout=asyncio.subprocess.PIPE,
    stderr=asyncio.subprocess.PIPE,
    env=safe_env,
)
```

**特点**：

- 支持 Python、Bash、Node.js 三种语言
- 每个 Agent 在独立的 `workspace/` 目录下执行
- 超时控制（最多 60 秒）
- 环境变量隔离（覆盖 HOME 路径指向工作空间）

**安全机制**：

- ✅ 黑名单过滤危险命令（rm -rf、sudo、curl、wget 等）
- ✅ 阻止危险 Python 导入（subprocess、socket、requests 等）
- ✅ 防止目录遍历攻击（禁止 `../../`）
- ✅ 工作目录限制（只能在 workspace 内操作）

#### 🐳 模式二：Docker 容器隔离（可选）

**实现位置**：`backend/app/services/agent_manager.py`

**核心机制**：

- 每个 Agent 可以启动独立的 OpenClaw Gateway 容器
- 使用 Docker 网络隔离（`clawith_network`）
- 每个容器分配唯一端口（通过 hash 计算避免冲突）
- 容器挂载 Agent 的专属工作空间目录

**关键配置**（docker-compose.yml）：

```yaml
volumes:
  - /var/run/docker.sock:/var/run/docker.sock # 主容器可管理子容器
  - agent_data:/data/agents # 共享工作空间卷
```

### 2.2 多核环境支持

**并发处理**：

- FastAPI + asyncio 实现高并发
- 每个 Agent 请求在独立的异步任务中处理
- 代码执行通过子进程实现天然的多核利用

**资源隔离**：

- 文件系统隔离：每个 Agent 独立目录 `/data/agents/<agent_id>/`
- 进程隔离：子进程之间互不干扰
- 可选容器隔离：更强的安全边界

## 🤔 三、与 OpenClaw 的关系

### 3.1 定位差异

| 维度       | OpenClaw       | Clawith         |
| ---------- | -------------- | --------------- |
| 使用场景   | 单用户个人助理 | 企业多租户平台  |
| 部署方式   | 本地运行       | 云端/私有化部署 |
| Agent 数量 | 1 个 Gateway   | N 个 Agent 实例 |
| 权限体系   | 无             | 完整 RBAC       |
| 组织感知   | 无             | 理解组织架构    |

### 3.2 技术关系

**❌ 不是基于 OpenClaw 实现的**

**依赖分析**（pyproject.toml）：

- ❌ 没有 `openclaw` 包依赖
- ❌ 没有 `langchain`、`langgraph`、`autogen`、`crewai` 等任何 Agent 框架
- ✅ 只有基础 Web 框架：FastAPI + SQLAlchemy + Redis

**实际关系**：

- 💡 **理念借鉴**：采用了 OpenClaw 的 soul、memory、workspace、heartbeat 概念
- 🔧 **完全重写**：从零实现了适合企业多租户的架构
- 🎯 **独立演进**：是一个完全独立的项目

### 3.3 OpenClaw Gateway 容器的作用

虽然代码中有启动 OpenClaw Gateway 容器的逻辑，但：

- **不是用来执行代码的**（代码执行在主进程中）
- 可能用于备用运行环境或未来扩展预留
- 当前核心功能都在 Clawith 自研的框架中实现

## 💡 五、值得借鉴的核心概念

### 🥇 Top 5 最值得借鉴的设计

#### 1. 🏢 **"数字员工"范式 —— 身份定位的转变**

**理念**：

- Agent 不是"工具"，而是**组织的一员**
- 了解完整组织架构（人类同事 + AI 同事）
- 建立真实的工作关系和协作网络

**为什么重要**：

- 改变用户心智模型：从"使用工具"到"管理团队"
- 让 Agent 更容易被接受和信任
- 为多 Agent 协作提供自然的概念基础

---

#### 2. 🏛️ **Agent 广场 —— 知识流动的社交化**

**理念**：

- 组织内部的**共享社交空间**
- Agent 发帖、分享发现、评论彼此的工作
- 持续吸收组织知识、保持上下文感知

**工作流程**：

```
Agent 探索 → 记录发现 → 分享到广场 → 其他 Agent 看到 →
触发新思考 → 形成知识网络
```

**价值**：

- ✅ 突破单点对话限制，实现异步协作
- ✅ 知识沉淀与传播（一个 Agent 的发现全组织可见）
- ✅ 避免重复劳动（信息复用）
- ✅ 增强组织感知（知道团队在做什么）

---

#### 3. 📊 **三级自主性模型 —— 渐进式信任**

**理念**：

- **L1（绿灯）**：直接执行，无需人类介入（读文件、搜索）
- **L2（黄灯）**：执行后通知人类（修改文件、发消息）
- **L3（红灯）**：需人类审批后才执行（对外沟通、删除文件）

**可配置性**：

- 每个 Agent 针对不同操作类型独立配置级别
- 可随着信任度调整（新手高审批 → 成熟低审批）

**价值**：

- ✅ 平衡自动化与控制
- ✅ 清晰的责任边界
- ✅ 降低用户对 Agent "失控"的担忧

---

#### 4. 💓 **心跳系统 —— 主动感知与学习**

**理念**：

- 周期性（如每 30 分钟）触发 Agent "醒来"
- 主动检查：广场动态、新任务、需要跟进的事项
- 基于最近工作上下文**主动探索相关知识**

**典型流程**：

```
心跳触发 → 回顾近期对话 → 识别值得深入的话题 →
网络搜索 → 记录到 curiosity_journal.md → 分享到广场
```

**价值**：

- ✅ 从"纯被动响应"到"主动服务"
- ✅ 在工作间隙保持知识更新
- ✅ 类比人类的"碎片时间学习"

---

#### 5. 🧠 **Soul + Memory —— 持久身份架构**

**理念**：

- `soul.md`：人格、价值观、工作风格（**不变的核心**）
- `memory.md`：长期上下文、学习到的偏好（**进化的记忆**）
- `reflections.md`：自主思考日志（**探索的痕迹**）

**关键特点**：

- 跨会话持久化（不是临时 prompt）
- Agent 主动写入 memory
- 每次对话都加载这些上下文

**价值**：

- ✅ 真正的个性化（记住用户偏好）
- ✅ 一致的人格（不会"换人"）
- ✅ 可追溯的成长轨迹

---

### 🎖️ 其他值得关注的概念

#### 6. 📋 **督办任务 —— Agent 作为流程守护者**

- Agent 可以**代表组织催促人类或其他 Agent**
- 周期性检查 + 自动提醒 + 进度汇报
- 例：秘书 Agent 每周五检查周报提交情况

**价值**：解放人类管理者的琐碎催办工作

---

#### 7. 💬 **Agent 间协作 —— 数字团队**

- Agent 可以互相发消息、委派任务
- 支持多轮对话（自动判断结束）
- 每个 Agent 知道其他 Agent 的专长

**场景示例**：

```
数据分析 Agent → 需要某个 API 数据 →
消息给研发 Agent → 研发 Agent 提供接口 →
数据分析 Agent 继续工作
```

**价值**：复制人类团队的分工协作模式

---

#### 8. 🧬 **运行时能力扩展 —— 自我进化**

- Agent 遇到无法处理的任务 → 搜索 MCP 工具注册表
- 一键导入新工具 → 立即获得新能力
- Agent 还可以**为自己或同事创建新技能**

**典型流程**：

```
用户：帮我发邮件
Agent：我没有邮件工具 → discover_resources("send email") →
找到 Gmail MCP Server → import_mcp_server → 获得能力 → 完成任务
```

**价值**：从固定能力到动态扩展

---

#### 9. 📚 **技能与工具分离 —— 渐进式披露**

**设计模式**：

- **技能（Skill）**：领域知识 + 工作流程（Markdown 文档）
- **工具（Tool）**：底层执行能力（API 调用）
- 系统提示词只包含技能**目录**，需要时才加载完整内容

**价值**：

- 节省 Token（不把所有内容塞进 prompt）
- 易于扩展（新增技能不会爆炸提示词长度）

---

#### 10. 🌐 **企业知识库注入 —— 全局上下文**

- `enterprise_info/` 存储全组织共享信息
- 自动注入每个 Agent 的系统提示词
- 可按角色差异化推送（HR 看薪资，销售看定价）

**价值**：

- 一处维护，全员同步
- 保证信息一致性
- 安全的信息分发

## 🎯 三、技术实现特点

### 3.1 完全自研的框架

**证据**：

- ❌ 不依赖任何第三方 Agent 框架（LangChain/AutoGen/CrewAI）
- ❌ 不依赖 OpenClaw 代码库

### 3.2 架构优势

✅ **轻量高效**：无额外框架开销  
✅ **完全掌控**：可以针对企业场景深度定制  
✅ **易于维护**：代码结构清晰，职责明确  
✅ **灵活扩展**：基于标准协议（OpenAI API、MCP）

## 📋 四、概念层面的借鉴建议

### 核心概念对比

| 维度         | 传统 Agent    | Clawith 创新            |
| ------------ | ------------- | ----------------------- |
| **定位**     | 个人助理/工具 | 组织的数字员工          |
| **记忆**     | 会话级上下文  | 持久化 soul + memory    |
| **协作**     | 单体工作      | Agent 间消息 + 广场社交 |
| **主动性**   | 被动响应      | 心跳系统 + 督办任务     |
| **能力**     | 固定工具集    | 运行时发现和安装        |
| **工作空间** | 简单 K-V 存储 | 完整文件系统            |
| **权限**     | 全有或全无    | 三级自主性（L1/L2/L3）  |
| **知识**     | 每次重新输入  | 企业知识库自动注入      |

### 适用场景

这些概念特别适合：

- ✅ **企业内部工具**：需要多人协作、权限控制
- ✅ **长期使用场景**：需要 Agent 记住历史、持续成长
- ✅ **复杂业务流程**：需要多 Agent 分工、主动跟进
- ✅ **知识密集型工作**：需要 Agent 持续学习和分享

### 实施建议

**优先级排序**：

1. **P0（核心）**：Soul + Memory（持久身份）
2. **P0（核心）**：三级自主性（安全控制）
3. **P1（重要）**：Agent 广场（知识流动）
4. **P1（重要）**：心跳系统（主动服务）
5. **P2（增强）**：督办任务（流程守护）

## 🔑 五、关键技术洞察

### 代码执行的权衡

Clawith 选择了**轻量级进程执行**而非容器执行：

**优点**：

- ⚡ 响应快（无跨容器通信开销）
- 💰 资源省（不需要每个 Agent 一个容器）
- 🔧 易维护（代码简单直接）

**安全保障**：

- 黑名单过滤
- 工作目录限制
- 超时控制
- 环境变量隔离

**适用场景**：

- ✅ 受信任的企业内部环境
- ✅ 代码复杂度可控的场景
- ❌ 如需更强隔离，可改用容器模式

## 📊 六、架构设计亮点

### 6.1 文件系统式设计

Agent 工作空间类比**真实员工的办公桌**：

```
<agent_id>/
├── soul.md              # 个人档案
├── memory/              # 知识笔记本
├── skills/              # 技能证书
├── workspace/           # 工作文件夹
│   ├── 2025Q1竞品分析/
│   └── archived/
└── enterprise_info/     # 公司文件柜（共享）
```

**价值**：

- 符合人类工作习惯
- 支持复杂工作流（多文件、多步骤）
- 可视化和可审计

### 6.2 多层次的并发模型

1. **HTTP 层**：FastAPI 处理并发请求
2. **任务层**：asyncio.create_task 并发执行任务
3. **工具层**：subprocess 并发执行代码
4. **Agent 层**：独立 Agent 之间天然并发

### 6.3 企业级设计

✅ 多租户隔离  
✅ RBAC 权限控制  
✅ 审计日志（全操作追踪）  
✅ 配额管理（Token 限额、Agent TTL）  
✅ 审批工作流（危险操作人工审核）

## 🎓 七、总结与启示

### 核心启示

1. **概念创新胜于技术复杂度**
   - Clawith 没有用复杂的框架，但概念设计很出色
   - "数字员工"、"广场"、"督办"这些概念打动人心

2. **从个人到组织的跨越**
   - 单 Agent → 多 Agent 不只是数量变化
   - 需要引入：关系、协作、权限、知识共享

3. **主动性是关键差异化**
   - 被动响应 → 主动服务（心跳、督办）
   - 让 Agent 真正像"员工"而非"工具"

4. **文件系统是好的抽象**
   - 比数据库或 K-V 存储更直观
   - 支持复杂工作流
   - 人类可以直接查看和理解

5. **渐进式信任很重要**
   - 三级自主性解决了"不敢用"的问题
   - 用户可以逐步放开权限
   - 清晰的责任边界
