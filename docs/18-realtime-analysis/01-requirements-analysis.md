# 实时分析模块 — 需求分析

> **撰写时间**: 2026-03-06
> **版本**: 1.0
> **模块名称**: LiveInsight（实时洞察）

---

## 1. 核心需求提炼

### 1.1 用户原始描述

用户描述了一个通用的"实时收集 + 实时分析"场景：

- 打开模块后，持续录音收集对话内容（我方 + 对方）
- 录音内容经过 ASR 转文字后，由 LLM 实时分析
- **分析目标可配置**（不同场景需要分析不同维度）
- **输出格式可配置**（标准化展示）
- 分析结果随着对话推进**不断刷新**
- 每次刷新的**原始素材 + 分析结果**都要保存（可回溯）
- 一次完整的对话形成一个**会话记录**，持久化存储
- 不仅是销售场景，还有专业服务、咨询等多种场景

### 1.2 需求拆解

| 编号 | 需求                                  | 类型       | 优先级 |
| ---- | ------------------------------------- | ---------- | ------ |
| R1   | 持续录音 → ASR 转写 → 文字流          | 数据采集   | P0     |
| R2   | 基于文字流的实时 LLM 分析             | 核心能力   | P0     |
| R3   | 分析目标/维度可配置（模板化）         | 配置能力   | P0     |
| R4   | 分析结果的标准化展示                  | 前端展示   | P0     |
| R5   | 分析快照（每次刷新的素材+结果）可回溯 | 数据持久化 | P1     |
| R6   | 会话级记录（一次完整对话）持久化      | 数据持久化 | P1     |
| R7   | 多分析维度并行（如销售+服务+情绪）    | 扩展能力   | P1     |
| R8   | 历史会话列表与深度回顾                | 数据复用   | P2     |
| R9   | 内置场景模板（销售、服务、会议等）    | 易用性     | P2     |

## 2. 场景分析

### 2.1 典型场景

#### 场景 A：销售对话分析

```
情境：销售人员拜访客户，笔记本电脑录音

实时分析维度（可配置）：
  ├─ 客户购买意愿：强烈 / 一般 / 观望 / 拒绝
  ├─ 客户真实需求：提取关键需求点
  ├─ 价格敏感度：高 / 中 / 低
  ├─ 决策阶段：了解 / 对比 / 谈判 / 签约
  ├─ 竞品提及：提取竞品信息
  └─ 下一步建议：给销售人员的实时建议

输出样例：
  ┌─────────────────────────────────────┐
  │ 🎯 客户意愿：一般 → 偏强           │
  │ 📋 核心需求：降低运维成本，自动化    │
  │ 💰 价格敏感度：中等                  │
  │ 🔄 决策阶段：对比阶段               │
  │ ⚠️  竞品提及：提到了 XX 产品         │
  │ 💡 建议：强调 ROI 数据，展示案例     │
  └─────────────────────────────────────┘
```

#### 场景 B：专业服务对话

```
情境：IT 顾问与客户讨论技术方案

实时分析维度（可配置）：
  ├─ 客户技术痛点：提取技术问题
  ├─ 方案匹配度：我方方案是否匹配
  ├─ 风险点：提取潜在风险
  ├─ 客户技术成熟度：高 / 中 / 低
  └─ 下一步行动项：待办事项列表
```

#### 场景 C：会议纪要

```
情境：团队会议录音

实时分析维度（可配置）：
  ├─ 议题摘要：当前讨论的主题
  ├─ 决策记录：已做出的决定
  ├─ 行动项：待办及责任人
  ├─ 分歧点：尚未达成一致的问题
  └─ 时间分配：各议题耗时占比
```

#### 场景 D：培训/面试评估

```
情境：面试官面试候选人

实时分析维度（可配置）：
  ├─ 技术能力评估：各维度打分
  ├─ 沟通表达能力：清晰度 / 逻辑性
  ├─ 关键回答摘要：亮点 / 疑点
  └─ 综合建议：通过 / 待定 / 淘汰
```

### 2.2 场景共性抽象

| 共性     | 说明                                |
| -------- | ----------------------------------- |
| **输入** | 持续的音频流 → ASR 转文字           |
| **处理** | 文字流 → LLM 分析 → 结构化结果      |
| **配置** | 分析维度 + 输出格式由"分析模板"定义 |
| **展示** | 结构化卡片 + 实时刷新               |
| **存储** | 原始文本 + 分析快照 + 会话记录      |
| **回溯** | 任意时间点的素材和结果都可查看      |

## 3. 核心概念定义

### 3.1 概念模型

```
LiveInsight（实时洞察模块）
│
├── AnalysisTemplate（分析模板）
│   ├── name: "销售对话分析"
│   ├── description: "实时分析客户购买意愿、需求、竞品等"
│   ├── dimensions: [            ← 分析维度列表
│   │   {
│   │     key: "purchase_intent",
│   │     label: "购买意愿",
│   │     type: "enum",          ← 维度类型
│   │     options: ["强烈", "一般", "观望", "拒绝"],
│   │     prompt: "根据对话内容判断客户的购买意愿..."
│   │   },
│   │   {
│   │     key: "core_needs",
│   │     label: "核心需求",
│   │     type: "list",
│   │     prompt: "提取客户表达的核心需求点..."
│   │   },
│   │   ...
│   │ ]
│   ├── analysisPrompt: "..."    ← 总体分析提示词
│   └── refreshStrategy: {       ← 刷新策略
│       trigger: "silence",      ← 触发方式：静音/定时/手动
│       interval: 30,            ← 定时间隔（秒）
│       minNewChars: 100         ← 最少新增字符数
│     }
│
├── InsightSession（洞察会话）
│   ├── id: "session-20260306-1430"
│   ├── templateId: "sales-analysis"
│   ├── startTime / endTime
│   ├── transcript: "..."        ← 完整转写文本（累积）
│   └── snapshots: [             ← 分析快照列表
│       {
│         id: "snap-001",
│         timestamp: 1709715600,
│         transcriptSlice: "从第 0 到第 500 字", ← 本次分析的文本范围
│         rawInput: "...",       ← 本次新增的原始文本
│         result: {              ← 分析结果
│           purchase_intent: "一般",
│           core_needs: ["降低成本", "自动化"],
│           ...
│         }
│       },
│       {
│         id: "snap-002",
│         timestamp: 1709715660,
│         transcriptSlice: "从第 0 到第 1200 字",
│         rawInput: "...",
│         result: { ... }        ← 随着信息增加，判断可能变化
│       }
│     ]
│
└── SnapshotTimeline（快照时间线）
    ← 用于回溯：查看任意快照时的素材和结果
    ← 对比：snap-001 vs snap-002 的变化
```

### 3.2 关键术语

| 术语       | 英文             | 说明                                 |
| ---------- | ---------------- | ------------------------------------ |
| 分析模板   | AnalysisTemplate | 定义分析目标、维度、格式、策略的配置 |
| 洞察会话   | InsightSession   | 一次完整的录音 + 分析过程            |
| 分析快照   | Snapshot         | 某一时刻的原始素材 + 分析结果        |
| 维度       | Dimension        | 单个分析指标（如"购买意愿"）         |
| 刷新策略   | RefreshStrategy  | 何时触发一次分析（静音/定时/手动）   |
| 快照时间线 | SnapshotTimeline | 所有快照按时间排列，支持回溯         |

## 4. 数据流分析

### 4.1 整体数据流

```
┌─────────────┐     ┌──────────────┐     ┌──────────────────┐     ┌──────────────┐
│  麦克风录音   │ ──→ │  ASR Worker   │ ──→ │   文本累积缓冲区   │ ──→ │  LLM 分析     │
│  (音频流)     │     │  (实时转写)    │     │  (transcript)     │     │  (Agent)      │
└─────────────┘     └──────────────┘     └──────────────────┘     └──────────────┘
                                                  │                        │
                                                  ↓                        ↓
                                          ┌──────────────┐       ┌──────────────┐
                                          │  Snapshot 存储 │       │  前端实时展示  │
                                          │  (回溯用)      │       │  (卡片刷新)   │
                                          └──────────────┘       └──────────────┘
```

### 4.2 刷新触发时序

```
时间线：
  t=0s    开始录音
  t=10s   ASR: "你好，今天来看看你们的产品..."
  t=25s   ASR: "我们目前用的是 XX 产品，但觉得..."
  t=30s   ← 静音检测 / 定时触发 → 执行第 1 次分析
          ┌──────────────────────────────────────────┐
          │ Snapshot #1                               │
          │ rawInput: "你好，今天来看看...但觉得..."  │
          │ result:                                    │
          │   purchase_intent: "观望"                  │
          │   core_needs: ["对比产品"]                  │
          │   competitor_mention: "XX 产品"             │
          └──────────────────────────────────────────┘

  t=45s   ASR: "价格方面能不能优惠..."
  t=55s   ASR: "如果能解决 XX 的问题，我们可以考虑..."
  t=60s   ← 触发第 2 次分析（带上全部文本，包含前面的）
          ┌──────────────────────────────────────────┐
          │ Snapshot #2                               │
          │ rawInput: "价格方面...可以考虑..."         │
          │ result:                                    │
          │   purchase_intent: "一般 → 偏强"  ← 变化！ │
          │   core_needs: ["对比产品", "解决XX问题"]   │
          │   price_sensitivity: "中等"                │
          │   next_action: "强调 ROI，展示成功案例"    │
          └──────────────────────────────────────────┘

  ... 不断累积、不断刷新 ...
```

### 4.3 分析模式选择

| 模式         | 说明                                 | 适用场景           |
| ------------ | ------------------------------------ | ------------------ |
| **增量分析** | 每次只分析新增文本，结合历史结果     | 长对话、节省 Token |
| **全量分析** | 每次用全部文本重新分析               | 短对话、精度优先   |
| **混合模式** | 前 N 次全量，之后增量 + 定期全量校正 | 平衡精度与成本     |

**推荐**：混合模式（前 3 次全量分析建立基线，之后增量 + 每 5 次全量校正）

## 5. 维度类型系统

### 5.1 支持的维度类型

分析模板中的每个维度需要定义类型，以便前端标准化展示：

```typescript
type DimensionType =
  | 'enum' // 枚举：从固定选项中选一个（如"强烈/一般/观望"）
  | 'score' // 评分：0-100 的数值
  | 'text' // 文本：自由文本描述
  | 'list' // 列表：多个条目的列表
  | 'boolean' // 布尔：是/否
  | 'tags' // 标签：多个标签
  | 'progress' // 进度：阶段性的进展（如"了解→对比→谈判→签约"）
  | 'comparison'; // 对比：与上次快照的变化趋势（↑↓→）
```

### 5.2 维度定义示例

```json
{
  "key": "purchase_intent",
  "label": "购买意愿",
  "type": "enum",
  "options": ["强烈", "一般", "观望", "拒绝"],
  "icon": "🎯",
  "prompt": "根据对话中客户的语气、措辞、提问方式，判断客户当前的购买意愿等级。注意区分礼貌性表达和真实意图。",
  "showTrend": true
}
```

```json
{
  "key": "core_needs",
  "label": "核心需求",
  "type": "list",
  "maxItems": 5,
  "icon": "📋",
  "prompt": "提取客户在对话中明确或隐含表达的核心需求。忽略寒暄和闲聊内容，聚焦在业务相关的需求点上。每个需求用一句话概括。"
}
```

## 6. 非功能性需求

| 维度       | 要求                                  |
| ---------- | ------------------------------------- |
| **延迟**   | 从静音检测到分析结果展示 < 5 秒       |
| **并发**   | 同时只支持一个活跃洞察会话            |
| **存储**   | 每个会话独立 JSON 文件，按日期组织    |
| **隐私**   | 录音数据仅本地处理，不上传            |
| **成本**   | 每次分析的 Token 开销可控（增量模式） |
| **可靠性** | 录音中断/网络波动不丢失已收集的数据   |
| **兼容性** | 复用现有 ASR Worker（端口 18100）     |

## 8. 风险与挑战

| 风险               | 影响             | 缓解措施                          |
| ------------------ | ---------------- | --------------------------------- |
| ASR 转写质量不稳定 | 分析结果不准确   | 全量模式兜底 + 人工纠错           |
| 口语化内容干扰     | LLM 分析偏离主题 | 分析 Prompt 强调过滤噪声          |
| 长对话 Token 超限  | 全量分析无法执行 | 自动切换增量模式 + 摘要压缩       |
| 分析延迟过高       | 实时感差         | 增量模式 + 流式输出               |
| 多人说话混淆       | 无法区分发言人   | 未来扩展说话人分离（diarization） |

## 9. 开放问题

以下问题需要在方案设计阶段进一步确认：

1. **模板创建方式**：用户手动编辑 JSON？还是通过 UI 表单创建？还是让 LLM 辅助生成？
   - **建议**：三种都支持。UI 表单为主，高级用户可编辑 JSON，LLM 辅助生成降低门槛。

2. **多语言支持**：是否需要支持非中文对话？
   - **建议**：Phase 1 先支持中文，ASR Worker 已支持中文。

3. **多人说话**：是否需要区分"我方"和"对方"？
   - **建议**：Phase 1 不区分（当前 ASR 不支持说话人分离）。Phase 2 可扩展。

4. **分析频率**：默认多久分析一次？
   - **建议**：默认"静音 + 最少 100 新字符"触发，可配置。

5. **离线使用**：是否需要支持无网络环境？
   - **建议**：ASR 已支持离线。LLM 需网络（除非用本地模型）。

## 10. 总结

### 10.1 模块定位

**LiveInsight（实时洞察）** 是一个通用的"实时数据采集 + AI 分析"模块，核心特点：

1. **采集通用化**：当前以录音 + ASR 为主要输入，未来可扩展其他数据源
2. **分析模板化**：分析目标、维度、格式通过模板配置，不硬编码
3. **结果标准化**：维度类型系统确保展示统一，前端组件可复用
4. **时间线可回溯**：每次分析的素材和结果都保存，支持回顾和深度分析
5. **会话可持久化**：完整对话记录按日期存储，支持历史查看

### 10.2 核心价值

```
传统方式：
  对话结束 → 凭记忆写笔记 → 遗漏大量信息

LiveInsight：
  对话进行中 → 实时分析 → 结构化洞察 → 自动保存
  对话结束后 → 完整回顾 → 深度分析 → 知识沉淀
```
