## 🔥 优先级 P0（最关键）

### 1. API 配额智能管理系统

**问题**: 你有 6000 次/5 小时的 API 配额，但没有调度机制，容易浪费或不够用。

**方案**: 实现一个**配额调度器**

#### 核心功能

```typescript
interface QuotaManager {
  // 1. 配额追踪
  getRemainingQuota(): { count: number; resetAt: Date };

  // 2. 任务优先级
  enqueue(task: Task, priority: 'urgent' | 'normal' | 'low'): Promise<void>;

  // 3. 成本预估
  estimateCost(task: Task): number; // 预估需要多少次 API 调用

  // 4. 智能调度
  schedule(): void; // 根据优先级和配额智能分配
}
```

#### UI 设计

**位置**: 全局状态栏右侧（Logs/Settings 之前）

```
[智库 ●] [酒馆 ●] [配额: 4520/6000 (3h22m)] [日志] [设置]
                     ↑ 点击展开详情面板
```

**详情面板**（Modal）:

```
配额状态
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
剩余: 4520 / 6000 (75.3%)
重置: 2h 22m 后

使用统计
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
本周期消耗: 1480 次
  - 对话: 1200 次 (81%)
  - 智库: 180 次 (12%)
  - 定时任务: 100 次 (7%)

待执行队列
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🔴 紧急 (3): 证券数据分析 | 预估 50 次
🟡 普通 (5): 日报生成 | 预估 120 次
🟢 低优先级 (2): 智库同步 | 预估 200 次
```

#### 实现路径

1. **Backend**: `src/main/quota/QuotaManager.ts`
   - 读取 API 提供商的 rate limit headers
   - 本地缓存配额状态（`.home/quota/status.json`）
   - 任务队列 + 优先级调度

2. **Frontend**: `src/renderer/src/stores/quota.ts` + `src/renderer/src/components/QuotaPanel.vue`
   - Pinia store 管理配额状态
   - 实时更新（通过 Gateway events）
   - 可视化图表（使用 Chart.js 或 ECharts）

3. **Integration**: 在 `AgentExecutor` 中集成，每次调用前检查配额

**优先级理由**: 这是你当前最头疼的问题，配额管理不好会直接影响使用体验。

```typescript
interface ExecutionTrace {
  timestamp: string;
```

3. **Store**: `useExecutionTrace()` composable 管理追踪数据

**优先级理由**: 可观测性是系统可信赖的基础，特别是当 Agent 自主执行时。

## ⚡ 优先级 P1（重要但不紧急）

### 4. Agent 自动路由（Smart Triage）

**问题**: 用户每次都要手动选择 Agent，系统无法自动匹配最合适的专家。

**方案**: 实现**智能分发器**

#### 工作流程

```
用户输入: "帮我分析这个交易数据的风险"
   ↓
系统分析:
  1. 提取关键词: 交易数据、风险
  2. 语义匹配: 计算与所有 Agent 的相似度
  3. 推荐排序:
     - 证券交易数据处理专家 (0.92)
     - 风险评估专家 (0.85)
     - 业务分析专家 (0.65)
   ↓
用户确认:
  • 自动使用"证券交易数据处理专家"
  • 或手动选择其他
```

#### 实现路径

1. **Semantic Matching**: 使用 Embedding 模型（如 `text-embedding-v3`）计算相似度
2. **历史优化**: 记录用户的选择偏好，逐步优化推荐
3. **UI**: 在输入框下方显示推荐的 Agent（类似 VSCode Copilot 的建议）

**技术栈**:

- Backend: `src/main/ai/routing/TriageService.ts`
- Frontend: `ChatPanel` 添加 Agent 推荐卡片
- Model: 使用 `dashscope/text-embedding-v3` 或本地 Sentence Transformer

### 8. 对话分支管理（Thread Branching）

**问题**: 对话只能线性进行，无法"回到某一步重新尝试"。

**方案**: 实现**对话分支**（参考 ChatGPT）

#### 交互设计

```
User: 帮我写一个函数
Agent: 好的，这是方案 A

→ [编辑并重新生成] ← 用户点击
  ↓ 创建分支

User: 帮我写一个函数
Agent: 好的，这是方案 B

→ 用户可以在分支 A/B 之间切换
```

#### 实现路径

1. **Backend**: Thread 存储支持树结构（当前是线性的）
2. **Frontend**: ChatPanel 显示分支导航（左右箭头）

**技术复杂度**: 中等（需要重构 Thread 存储和渲染逻辑）

## 💡 关键设计原则

### 1. 渐进式增强

```
当前: Agent 能用 → P0: Agent 好用 → P1: Agent 智能 → P2: Agent 生态
```

### 2. 数据驱动决策

- 每个功能都应该有**可量化的改进指标**
- 例如：配额管理 → 衡量"配额利用率"和"任务完成率"
- 例如：自动路由 → 衡量"路由准确率"和"用户确认率"

### 3. 用户自主控制

- 自动化很好，但要保留**手动干预**的能力
- 例如：自动路由推荐 Agent A，但用户可以选 Agent B
- 例如：配额智能调度，但用户可以手动提升某任务优先级

### 4. 性能优先

- 所有 UI 操作必须**快速响应**（< 100ms）
- 耗时操作（LLM 调用、文件搜索）使用 **SSE 流式反馈**
- 大数据集（智库、Memory）使用**虚拟滚动**和**分页加载**

## 🚧 技术债务（建议修复）

### 1. TypeScript 严格模式

**当前**: `tsconfig` 使用 `strict: false`

**建议**: 逐步迁移到严格模式

- 先修复 `src/main/`（后端代码）
- 再修复 `src/renderer/`（前端代码）
- 最后修复 `src/shared/`（共享类型）

**好处**: 减少运行时类型错误，提升代码质量

### 2. 测试覆盖率

**当前**: 部分核心模块有测试，但覆盖率不足

**建议**:

- 核心模块（AgentStore, SkillManager, ToolExecutionPipeline）→ 80% 覆盖
- 工具实现（builtin tools）→ 60% 覆盖
- UI 组件 → 暂不强制（成本高）

### 3. 日志分级和结构化

**当前**: 日志混杂在一起，难以过滤

**建议**: 使用结构化日志

```typescript
log.info('Agent executed', {
  agentId: 'code-reviewer',
  duration: 4520,
  toolCalls: 8,
  tokensUsed: 12450
});
```

**好处**: 便于后续分析和告警
