# 通用经验管理系统（三层结构）

## 核心理念

**三层树形结构 + 完全自动化 + 通用化设计**

```
问题（第1层）
  └─ 解决思路（概要）
      ├─ 解决方案1（第2层 + 第3层）
      │   ├─ 具体实现（代码/配置/步骤）
      │   └─ 推导过程（为什么这样做）
      ├─ 解决方案2
      └─ 解决方案3...
```

**设计优势**：

- ✅ **支持多方案对比**：同一问题，多种解决路径
- ✅ **推导可追溯**：第3层记录"为什么"
- ✅ **完全自动化**：大模型自主决策，无需人工触发
- ✅ **通用化**：任何skill都可使用
- ✅ **本地存储**：MD格式，保护隐私，支持Git管理

## 核心流程

### 🔄 完全自动化的三个时机

```
┌─────────────────────────────────────────────┐
│ ① 执行前：自动查询经验库                    │
│    → 找到类似问题 → 推荐已验证方案          │
│                                              │
│ ② 执行中：遇到困难自动查备选方案             │
│    → 检索失败 → 查询其他方案                │
│                                              │
│ ③ 执行后：自动判断是否沉淀                  │
│    → 复杂场景/遇到困难 → 自动保存经验        │
└─────────────────────────────────────────────┘
```

**用户视角**：完全透明，无需人工干预

## 自动化机制

### 🔍 时机1：执行前自动查询

**触发**：任意skill开始执行时

**逻辑**：

1. 提取用户输入的关键词
2. 在 `problems/_index.md` 中快速搜索匹配问题
3. 找到 → 提示用户并推荐已验证方案
4. 未找到 → 完全静默，继续正常流程

```
【自动】查询经验库（<1秒）
  ├─ 找到 → "🔍 找到相关经验：P001（推荐S001，成功率95%）"
  │          "[使用/跳过]"
  └─ 未找到 → 【静默】继续
```

---

### 🛠️ 时机2：执行中自动查备选方案

**触发**：遇到困难（操作失败、冲突、无法判断等）

**逻辑**：

1. 识别困难类型
2. 在经验库中搜索类似失败场景
3. 找到备选方案 → 自动切换
4. 未找到 → 记录新的失败模式

```
遇到困难
  ↓
【自动】查询备选方案
  ├─ 找到 S002 → "🔄 自动尝试备选方案"
  └─ 未找到 → 【记录失败模式】
```

---

### 💾 时机3：执行后自动沉淀

**触发条件**（满足任一即沉淀）：

- 执行过程中遇到过困难
- 场景复杂度高（如引用资源≥3个）
- 找到新方法（经验库中没有记录）
- 执行时间较长（超过5分钟）
- 用户明确要求

**流程**：

```
执行完成
  ↓
【自动】判断是否需要沉淀
  ↓（满足条件）
【自动】提取关键信息
【自动】创建问题和方案文件
【自动】更新索引和统计
  ↓
"✅ 经验已自动保存：P00X/S001"
```

## 问题编号分段规则

为支持多个skill共享同一经验库，问题编号按skill前缀分段：

| 编号段    | 分配给       | 说明        |
| --------- | ------------ | ----------- |
| P001-P099 | skill-A      | 默认起始段  |
| P100-P199 | skill-B      | 第二个skill |
| P200-P299 | skill-C      | 第三个skill |
| P1000+    | 通用/跨skill | 跨领域经验  |

**注意**：实际分配根据项目需求自行定义，在 `_index.md` 中声明。

## 与业务Skill的集成

### 方式一：在业务Skill的SKILL.md中声明（推荐）

在业务skill的核心流程部分增加：

```markdown
**🤖 已集成经验管理系统**（自动执行，用户无感知）：

1. 执行前：自动查询类似问题并推荐已验证方案
2. 执行中：遇到困难自动切换备选方案
3. 执行后：满足条件自动沉淀经验

详见：[experience-manager](../experience-manager/SKILL.md)
```

### 方式二：大模型自动识别

无需修改业务skill，大模型执行时会自动检测并调用经验管理机制。

## 💡 核心价值

1. **一问多解** — 同一个问题积累多种解决方案，按成功率推荐
2. **推导可追溯** — 第3层记录"为什么"，便于学习和Debug
3. **完全自动化** — 执行前查询、执行中切换、执行后沉淀，用户无感知
4. **通用化** — 不限领域，任何skill均可接入
5. **本地隐私** — MD文件存储，支持Git版本管理
