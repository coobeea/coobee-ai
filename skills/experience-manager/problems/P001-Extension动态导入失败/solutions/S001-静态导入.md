## 一、具体实现

### 修改前（❌ 失败）

```typescript
// extensions/discussion-channel/DiscussionChannel.ts
export function createDiscussionChannel(extensionApi: ExtensionApi) {
  return {
    inbound: {
      handleMessage: async (msg: InboundMessage) => {
        // ❌ 运行时动态导入（嵌套 jiti）
        const { ConsensusDetector } = await import('../../src/main/ai/discussion/ConsensusDetector');
        const detector = new ConsensusDetector();
        // ...
      }
    }
  };
}
```

### 修改后（✅ 成功）

```typescript
// extensions/discussion-channel/DiscussionChannel.ts
import { ConsensusDetector } from '../../src/main/ai/discussion/ConsensusDetector'; // ← 顶层静态导入

export function createDiscussionChannel(extensionApi: ExtensionApi) {
  return {
    inbound: {
      handleMessage: async (msg: InboundMessage) => {
        // ✅ 直接使用（无嵌套 jiti）
        const detector = new ConsensusDetector();
        // ...
      }
    }
  };
}
```

## 二、推导过程（为什么）

### 问题根因

1. Extension 被 `jiti` 动态加载
2. Extension 方法中 `await import()` 保留 jiti 上下文
3. 嵌套 jiti 导入时，`electron` 模块的 `app` 对象为 `undefined`

### 解决原理

**静态导入在 Extension 加载时就完成**，避免了运行时的嵌套 jiti 调用：

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. ExtensionLoader (jiti) 加载 Extension                       │
│    → import { ConsensusDetector } from '...' ← 此时完成导入    │
└─────────────────────────────────────────────────────────────────┘
                                ↓
┌─────────────────────────────────────────────────────────────────┐
│ 2. Extension 返回 ChannelPlugin 对象（包含 handleMessage）     │
│    → handleMessage 中直接使用 ConsensusDetector ← 无 import    │
└─────────────────────────────────────────────────────────────────┘
```

### 权衡取舍

**优点**：

- ✅ 实现简单，改动最小
- ✅ 无运行时开销
- ✅ 适用于所有场景

**缺点**：

- ⚠️ 增加 Extension bundle 大小（每个 Extension 都会打包导入的模块）
- ⚠️ 不支持按需加载（Extension 加载时就导入所有依赖）

**适用范围**：

- ✅ 简单工具类（如 ConsensusDetector）
- ✅ 不频繁变更的稳定模块
- ❌ 大型模块（考虑 S002 依赖注入）
- ❌ 可选功能（考虑 S003 缓存或 S002 注入）

## 四、注意事项

1. ✅ 使用相对路径 `../../src/main/*`（jiti 不支持 @main/\* 别名）
2. ✅ 检查导入模块是否在顶层调用 `createLogger()`
3. ✅ 如果模块很大，考虑 S002 依赖注入
