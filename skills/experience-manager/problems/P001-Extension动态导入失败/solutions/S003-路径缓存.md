### 修改后（✅ 成功）

```typescript
// extensions/workspace-file-watcher/WorkspaceFileWatcher.ts
export class WorkspaceFileWatcher {
  /** 缓存的 workspacesDir 路径（在 start() 时获取） */
  private workspacesDir: string | null = null;

  async start(ctx: ChannelContext) {
    // ✅ 在 start() 阶段获取并缓存路径（app 已就绪）
    try {
      const envModule = await import('../../src/main/common/env');
      const Env = envModule.Env || envModule.default;

      if (!Env || !Env.paths || !Env.paths.workspacesDir) {
        ctx.log.error('[Watcher] Failed to get workspacesDir');
        this.workspacesDir = null;
      } else {
        this.workspacesDir = Env.paths.workspacesDir;
        ctx.log.info(`[Watcher] Cached workspacesDir: ${this.workspacesDir}`);
      }
    } catch (err) {
      ctx.log.error('[Watcher] Failed to import Env:', err);
      this.workspacesDir = null;
    }
  }

  async startWatch(threadId: string) {
    // ✅ 使用缓存的路径（无动态导入）
    if (!this.workspacesDir) {
      log.error(`[Watcher] workspacesDir not available, cannot start watch for ${threadId}`);
      return;
    }

    const watchPath = path.join(this.workspacesDir, threadId);
    // ...
  }
}
```

## 二、推导过程（为什么）

### 问题根因

运行时频繁动态导入 `Env`，每次都会触发模块初始化，可能导致：

1. 在 jiti 嵌套上下文中失败（`app` 对象 `undefined`）
2. 性能开销（重复导入）

### 解决原理

**在安全时机（start() 生命周期）获取并缓存路径**：

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. Extension start() 被调用（app.whenReady 后）               │
└─────────────────────────────────────────────────────────────────┘
                                ↓
┌─────────────────────────────────────────────────────────────────┐
│ 2. 在 start() 中动态导入 Env ← ✅ app 已就绪                  │
│    → this.workspacesDir = Env.paths.workspacesDir ← 缓存       │
└─────────────────────────────────────────────────────────────────┘
                                ↓
┌─────────────────────────────────────────────────────────────────┐
│ 3. 运行时直接使用缓存路径 ← 无动态导入                         │
│    → const watchPath = path.join(this.workspacesDir, ...)      │
└─────────────────────────────────────────────────────────────────┘
```

### 权衡取舍

**优点**：

- ✅ 轻量级（只缓存必要信息）
- ✅ 无运行时开销（避免重复导入）
- ✅ 不增加 ExtensionApi 方法
- ✅ 适用于路径/配置等静态信息

**缺点**：

- ⚠️ 需要管理缓存生命周期
- ⚠️ 缓存可能过时（如果路径动态变更）
- ⚠️ 仅适用于路径场景，不适用于复杂对象

**适用范围**：

- ✅ 只需要文件路径（workspacesDir, configDir）
- ✅ 配置项（不频繁变更）
- ❌ 复杂对象（用 S002 依赖注入）
- ❌ 简单类（用 S001 静态导入）

## 四、最佳实践

### 何时使用路径缓存？

1. ✅ Extension 只需要文件路径或简单配置
2. ✅ 路径不会在运行时变更
3. ✅ 想避免修改 ExtensionApi
4. ✅ 需要多次访问同一路径（性能优化）

### 缓存时机

- ✅ 在 `start()` 生命周期中缓存（推荐）
- ✅ 在 `register()` 中缓存（如果不依赖 ChannelContext）
- ❌ 在 `handleMessage()` 等运行时方法中缓存（太晚了）

### 错误处理

```typescript
if (!this.workspacesDir) {
  log.error('[Extension] Path not available, operation skipped');
  return; // 优雅降级
}
```
