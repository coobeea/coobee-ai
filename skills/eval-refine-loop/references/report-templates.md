# 报告模板

## 1. 单轮评估报告（round-N.md）

```markdown
# {主题} 评估报告 · 第 {N} 轮

**评估时间**：YYYY-MM-DD HH:mm
**维度体系来源**：{dimension-analysis.md 路径}
**优化策略**：{A/B/C/首轮无}

## 总览

| 指标      | 值                         |
| --------- | -------------------------- |
| 维度总数  | X                          |
| ✅ 达标   | X                          |
| ⚠️ 待改进 | X                          |
| ❌ 不达标 | X                          |
| 达标率    | XX%                        |
| 综合判定  | 通过 / 有条件通过 / 不通过 |

## 逐维度评估

| 维度    | 权重 | 覆盖度   | 准确性   | 深度 | 相关性 | 判定 | 问题摘要   |
| ------- | ---- | -------- | -------- | ---- | ------ | ---- | ---------- |
| {维度1} | XX%  | 完整覆盖 | 正确     | 充分 | 相关   | ✅   | —          |
| {维度2} | XX%  | 部分覆盖 | 部分正确 | 不足 | 相关   | ⚠️   | {简要描述} |
| {维度3} | XX%  | 未覆盖   | —        | —    | —      | ❌   | 维度未覆盖 |

## 问题清单

| #   | 维度     | 问题类型 | 严重程度 | 问题描述   | 修正指令         |
| --- | -------- | -------- | -------- | ---------- | ---------------- |
| 1   | {维度名} | 遗漏     | 高       | {具体描述} | {对应的优化指令} |
| 2   | {维度名} | 错误     | 高       | {具体描述} | {对应的优化指令} |
| 3   | {维度名} | 不足     | 中       | {具体描述} | {对应的优化指令} |

## 优化决策

**策略选择**：{A/B/C}
**选择原因**：{问题维度占比 XX%，符合策略X的条件}
**预期改进**：{预计本轮优化后可解决的问题}
```

## 2. 最终闭环报告（final.md）

```markdown
# {主题} 质量闭环报告

**执行时间**：YYYY-MM-DD
**总轮次**：N
**退出原因**：全部达标 / 达到最大轮次 / 收敛瓶颈 / 策略C升级
**最终达标率**：XX%
**最终判定**：通过 / 部分通过 / 未通过

## 迭代轨迹

| 轮次 | 达标率 | ✅  | ⚠️  | ❌  | 问题数 | 策略 | 关键变化                |
| ---- | ------ | --- | --- | --- | ------ | ---- | ----------------------- |
| 1    | 40%    | 2   | 1   | 3   | 5      | B    | 首轮评估，问题较多      |
| 2    | 75%    | 4   | 2   | 0   | 2      | A    | 修复3个遗漏，消除不达标 |
| 3    | 100%   | 6   | 0   | 0   | 0      | —    | 全部达标                |

## 最终逐维度状态

| 维度    | 权重 | 最终判定  | 改进历程                                     |
| ------- | ---- | --------- | -------------------------------------------- |
| {维度1} | XX%  | ✅ 达标   | 首轮即达标                                   |
| {维度2} | XX%  | ✅ 达标   | 第1轮遗漏 → 第2轮补充 → 第3轮达标            |
| {维度3} | XX%  | ⚠️ 待改进 | 第1轮错误 → 第2轮纠正但深度不足 → 未完全解决 |

## 遗留问题（如有）

| 维度     | 问题   | 卡点原因 | 建议       |
| -------- | ------ | -------- | ---------- |
| {维度名} | {描述} | {根因}   | {建议动作} |

## 质量改进建议

基于本次闭环，以下改进可提升未来输出质量：

1. **{建议1}**：{具体描述}
2. **{建议2}**：{具体描述}
```

## 3. 卡点报告（策略C触发时，替代 final.md）

```markdown
# {主题} 卡点报告

**触发时间**：YYYY-MM-DD
**当前轮次**：第 N 轮
**当前达标率**：XX%

## 卡点分析

| 卡点维度 | 持续轮次 | 问题类型 | 历次修正尝试             | 诊断根因   |
| -------- | -------- | -------- | ------------------------ | ---------- |
| {维度名} | N轮      | {类型}   | {第1轮做了X，第2轮做了Y} | {根因判断} |

## 根因分类

### 维度定义问题

{如有，描述哪些维度定义存在歧义或不完整}
**建议**：启动 dimension-architect 迭代操作，优化以下维度的定义：{维度列表}

### 领域知识不足

{如有，描述LLM在哪些专业领域缺乏知识}
**建议**：补充以下参考资料后重试：{资料描述}

### 输入信息不足

{如有，描述哪些维度因原始输入信息不足而无法评估}
**建议**：请补充以下信息：{信息清单}

## 可继续部分

当前已达标的维度（达标率 XX%）的分析结果可先行使用，卡点维度待解决后补充。
```
