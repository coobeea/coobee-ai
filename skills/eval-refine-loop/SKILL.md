# 评估-优化闭环（Eval-Refine Loop）

## 核心职责

读取**维度体系** + **LLM输出** → 自动完成「评估 → 报告 → 诊断 → 优化 → 再评估」全闭环，直到输出质量达标。

## 前置依赖

- `dimension-architect` 产出的**领域 Skill**（包含 `references/dimensions.md`）
- 待评估的 LLM 输出内容（即领域 Skill 的执行结果）

## 核心流程

```
LLM输出 + 维度体系
  → ⓪ 经验检索（匹配已有领域经验）
  → ① 维度对齐评估
  → ② 差距报告
  → ③ 问题诊断
  → ④ 优化执行
  → ⑤ 重新评估
  → (循环，直到通过或达到退出条件)
  → ⑥ 经验沉淀
```

---

## Phase 0: 经验检索（每次启动必执行）

1. 读取 `cases/_index.md` 获取已有经验索引
2. 根据本次评估的**领域关键词**匹配已有案例
3. 有匹配 → 读取对应经验文件，提取：
   - **预警信息**：该领域 LLM 常见弱点（哪些维度容易出问题、什么类型的错误最多）
   - **策略建议**：该领域推荐的优化策略和参数调整
   - **避坑经验**：过去踩过的坑和解决方案
4. 无匹配 → 使用默认参数，正常进入 Phase 1

**检索优先级**：精确领域匹配 > 相似领域匹配 > 默认配置

**经验应用方式**：

- 预警信息 → 在 Phase 1 评估时对高风险维度加强检测
- 策略建议 → 在 Phase 4 策略选择时优先采用历史有效策略
- 参数建议 → 覆盖默认参数（如某领域建议最大轮次为 4）

## Phase 1: 维度对齐评估

### 输入准备

1. 读取 `{领域 Skill 目录}/references/dimensions.md`，提取维度定义和评估标准
2. 接收 LLM 输出内容（领域 Skill 的执行结果）

### 逐维度四项检测

对每个维度执行：

| 检测项 | 说明                       | 取值                         |
| ------ | -------------------------- | ---------------------------- |
| 覆盖度 | 该维度是否被分析           | 完整覆盖 / 部分覆盖 / 未覆盖 |
| 准确性 | 分析结论是否正确           | 正确 / 部分正确 / 错误       |
| 深度   | 是否达到评估标准要求的粒度 | 充分 / 不足 / 严重不足       |
| 相关性 | 内容是否与维度定义直接相关 | 相关 / 部分偏离 / 完全偏离   |

### 维度判定规则

- 四项全优 → ✅ **达标**
- 任一项为最低档（未覆盖/错误/严重不足/完全偏离） → ❌ **不达标**
- 其余情况 → ⚠️ **待改进**

---

## Phase 2: 差距报告

### 综合判定

| 达标率        | 判定          | 后续动作               |
| ------------- | ------------- | ---------------------- |
| 100%          | ✅ 通过       | 输出最终报告，退出循环 |
| ≥70% 且无❌   | ⚠️ 有条件通过 | 进入优化               |
| <70% 或存在❌ | ❌ 不通过     | 必须优化               |

### 报告内容

1. **总览**：维度总数、达标/待改进/不达标数、达标率、综合判定
2. **逐维度明细**：每个维度的四项检测结果 + 具体问题描述
3. **问题清单**：按严重程度（高/中/低）排序

报告格式详见 [report-templates.md](references/report-templates.md)

---

## Phase 3: 问题诊断

### 问题分类

对每个不达标/待改进维度，诊断问题类型：

| 问题类型 | 特征             | 优化指令模式                                                               |
| -------- | ---------------- | -------------------------------------------------------------------------- |
| 遗漏     | 维度完全未覆盖   | "请针对【{维度名}】进行分析，评估标准：{标准}"                             |
| 错误     | 结论与标准不符   | "你对【{维度名}】的判断有误：{具体错误}。正确的分析应考虑：{要点}"         |
| 不足     | 分析深度不够     | "请深化【{维度名}】的分析，当前缺少：{缺失要素}，需达到标准：{标准}"       |
| 偏离     | 内容与维度不匹配 | "你对【{维度名}】的分析偏离了维度定义。该维度衡量的是：{定义}，请重新分析" |
| 冗余     | 含无关内容       | "请移除以下与维度无关的内容：{冗余概述}"                                   |

详细分类体系和示例见 [problem-taxonomy.md](references/problem-taxonomy.md)

### 严重程度评定

| 严重程度 | 判定条件                                             |
| -------- | ---------------------------------------------------- |
| 高       | 影响核心结论（错误类） 或 高权重维度未覆盖（遗漏类） |
| 中       | 影响完整性（不足类、偏离类） 或 低权重维度遗漏       |
| 低       | 影响专业度（冗余类、轻微不足）                       |

## Phase 4: 优化执行

### 策略选择（自动判定）

```
问题维度占比 ≤ 30%           → 策略A: 针对性修正
问题维度占比 > 30%           → 策略B: 引导式重生成
连续2轮相同问题未解决        → 策略C: 升级处理
```

### 策略A: 针对性修正

适用：问题少，大部分输出质量达标。

1. 按严重程度降序排列问题
2. 为每个问题生成精确修正指令（格式见 Phase 3 表格）
3. 打包所有修正指令，连同原始输出一起发送给 LLM
4. 要求 LLM 保留达标部分不动，仅修正问题部分

### 策略B: 引导式重生成

适用：问题多，逐条修效率低。

1. 生成「失败分析摘要」— 汇总所有问题的模式和根因
2. 提取上一轮输出中**达标部分**作为「保留要求」
3. 将完整维度体系（含评估标准）作为**硬约束**附加
4. 要求 LLM 重新生成完整输出，同时附上失败摘要作为「避坑指南」

### 策略C: 升级处理

适用：自动修正连续 2 轮无效。

诊断卡点原因并给出建议：

| 卡点原因         | 信号                       | 建议动作                                    |
| ---------------- | -------------------------- | ------------------------------------------- |
| 维度定义有歧义   | 同一维度反复偏离/错误      | → 建议回到 dimension-architect 优化维度定义 |
| LLM 缺乏领域知识 | 专业维度持续错误           | → 补充领域参考资料后重试                    |
| 输入信息不足     | 多个维度因"信息不足"未覆盖 | → 标记需补充输入，暂停循环                  |

策略C 是唯一可能中断全自动循环的情况，此时输出卡点报告供用户决策。

## Phase 5: 循环控制

### 自动循环协议

```
轮次 = 1
while (轮次 ≤ 最大轮次) {
    执行 Phase 1-2（评估 + 报告）

    if (综合判定 == "通过") {
        输出最终报告 → 退出
    }

    if (轮次 > 1 && 本轮达标率 - 上轮达标率 < 改进阈值) {
        标记"收敛瓶颈" → 输出现状报告 → 退出
    }

    执行 Phase 3-4（诊断 + 优化）

    if (策略C触发) {
        输出卡点报告 → 退出
    }

    轮次++
}
输出最终报告（含"达到最大轮次"标记）
```

### 默认参数

| 参数          | 默认值 | 说明                            |
| ------------- | ------ | ------------------------------- |
| 最大轮次      | 3      | 超过则停止，避免无限循环        |
| 改进阈值      | 5%     | 达标率提升不足此值视为收敛      |
| 策略切换阈值  | 30%    | 问题维度占比超过此值切换到策略B |
| 策略C触发条件 | 2轮    | 同一问题连续N轮未解决           |

参数可由用户在启动时覆盖。

## 数据落地

### 目录结构

**用户项目目录**（每次评估的报告）：

```
{项目目录}/
├── dimension-analysis.md              # (来自 dimension-architect)
├── eval-reports/                      # 评估报告目录
│   └── YYYY-MM-DD-{主题}/
│       ├── round-1.md                 # 第1轮评估报告
│       ├── round-2.md                 # 第2轮（如有）
│       └── final.md                   # 最终闭环报告
```

**Skill 经验库目录**（Skill 自身积累）：

```
eval-refine-loop/
├── cases/                             # 经验库
│   ├── _index.md                      # 索引
│   └── {领域}-{场景}-eval.md          # 经验案例
```

### 落地时机

| 时机         | 落地内容     | 文件位置                                           |
| ------------ | ------------ | -------------------------------------------------- |
| 每轮评估完成 | 该轮评估报告 | `{项目}/eval-reports/YYYY-MM-DD-{主题}/round-N.md` |
| 循环结束     | 最终闭环报告 | `{项目}/eval-reports/YYYY-MM-DD-{主题}/final.md`   |
| 循环结束后   | 经验沉淀     | `eval-refine-loop/cases/{领域}-{场景}-eval.md`     |

报告格式详见 [report-templates.md](references/report-templates.md)

## 操作类型判断

| 类型       | 触发示例                       | 行为                                   |
| ---------- | ------------------------------ | -------------------------------------- |
| 全自动闭环 | "跑一下质量闭环""自动评估优化" | 执行完整 Phase 1-5 循环，落地报告      |
| 仅评估     | "帮我评估一下这个输出"         | 仅执行 Phase 1-2，生成报告，不自动优化 |
| 查看报告   | "上次评估结果怎么样"           | 只读已有报告，不写文件                 |
| 调参       | "最大轮次改成5"                | 更新循环参数，下次执行生效             |

---

## 闭环执行期间的汇报策略

全自动模式下，按以下节奏向用户汇报：

- **每轮评估后**：1-2 行汇报达标率和关键变化（如"第2轮：达标率从 40% 提升到 75%，修复了维度3遗漏和维度5错误"）
- **策略切换时**：说明切换原因（如"问题较多，切换到引导式重生成"）
- **循环结束后**：呈现完整最终报告

## 三 Skill 协作体系

```
dimension-architect          领域 Skill              eval-refine-loop
     │                      (如：合同审查)                  │
     │  生成领域 Skill        │                            │
     │ ──────────────────→   │                            │
     │                      │  处理实际任务               │
     │                      │  (审查合同等)               │
     │                      │ ─────────────────────────→  │  读取 references/dimensions.md
     │                      │                            │  评估 Skill 输出质量
     │                      │  ←───── 优化后的输出 ─────  │  自动优化闭环
     │                      │                            │
     │  ←──────────────── 反馈：维度定义有歧义 ──────────  │  策略C触发
     │                      │                            │
     │  优化维度 + 更新 Skill │                            │
     │ ──────────────────→   │  使用优化后的 Skill 重新处理 │
```

- `eval-refine-loop` 读取领域 Skill 的 `references/dimensions.md` 作为评估基准
- 当策略C诊断出"维度定义有歧义"时，建议用户启动 `dimension-architect` 的迭代操作
- 优化后的维度会同步更新领域 Skill 的 `references/dimensions.md` 和 `SKILL.md`

## Phase 6: 经验沉淀

### 触发条件

每次闭环完整执行完毕（无论通过/未通过/卡点），自动执行经验沉淀。

### 沉淀什么

与 `dimension-architect` 沉淀"用什么维度"不同，本 Skill 沉淀**评估和优化过程中的规律**：

| 经验类型     | 内容                         | 复用价值               |
| ------------ | ---------------------------- | ---------------------- |
| LLM 弱点模式 | 哪些维度容易出什么类型的问题 | 下次评估同领域时预警   |
| 策略有效性   | 哪种策略对哪类问题最有效     | 下次直接选最优策略     |
| 参数调优     | 最大轮次、阈值等参数的最优值 | 下次自动调参           |
| 问题分布规律 | 各类问题的占比分布           | 预判问题类型           |
| 卡点记录     | 哪些问题自动优化解决不了     | 提前告知用户需人工介入 |

### 沉淀流程

1. 从本次闭环的 `final.md` 中提取关键数据
2. 归纳可复用的规律
3. 写入案例文件 → `cases/{领域}-{场景}-eval.md`
4. 更新索引 → `cases/_index.md`

### 经验库目录结构

```
eval-refine-loop/
├── cases/
│   ├── _index.md                      # 索引
│   └── {领域}-{场景}-eval.md          # 经验案例
```

### 案例文件格式

```markdown
# {领域} · {场景} · 评估优化经验

**创建日期**：YYYY-MM-DD
**更新日期**：YYYY-MM-DD
**累计闭环次数**：N

## 领域概要

[领域和场景描述，维度数量]

## LLM 弱点模式

| 维度     | 常见问题类型 | 出现频率  | 说明               |
| -------- | ------------ | --------- | ------------------ |
| {维度名} | 遗漏         | 高(3/3次) | {为什么容易遗漏}   |
| {维度名} | 错误         | 中(1/3次) | {什么场景下容易错} |

## 策略有效性

| 场景             | 推荐策略     | 原因                                   |
| ---------------- | ------------ | -------------------------------------- |
| 首轮问题多(>50%) | 策略B        | 该领域维度间关联性强，逐条修不如重生成 |
| 税务维度持续错误 | 补充参考资料 | LLM 缺乏专业税务知识                   |

## 推荐参数

| 参数     | 推荐值 | 默认值 | 调整原因                  |
| -------- | ------ | ------ | ------------------------- |
| 最大轮次 | 4      | 3      | 该领域维度多，3轮不够收敛 |

## 问题分布

| 问题类型 | 平均占比 | 趋势 |
| -------- | -------- | ---- |
| 遗漏     | 40%      | 稳定 |
| 错误     | 20%      | 下降 |
| 不足     | 25%      | 稳定 |

## 关键经验

- **有效做法**：{什么做法特别有效}
- **避坑经验**：{什么情况下会卡住、怎么解决}
- **改进建议**：{对维度体系或评估流程的改进建议}
```

### \_index.md 索引格式

```markdown
# 评估优化经验库索引

| 领域 | 场景     | 闭环次数 | 平均轮次 | 平均最终达标率 | 关键词           | 文件                                           |
| ---- | -------- | -------- | -------- | -------------- | ---------------- | ---------------------------------------------- |
| 法律 | 合同审查 | 3        | 2.3      | 95%            | 合同,税务,增值税 | [法律-合同审查-eval.md](法律-合同审查-eval.md) |
```

### 经验迭代

同一领域+场景的案例文件会被持续更新：

- 每次闭环结束后，用最新数据更新统计（出现频率、问题分布等）
- 新发现的 LLM 弱点模式追加记录
- 策略有效性根据最新结果修正
- 更新"累计闭环次数"和"更新日期"
